# FunctionTemplate compact recipe：正式需求

## 1. 目标

将 class literal 中按方法独立分配的 40 B FunctionTemplate 替换为 ClassLiteral 级 compact recipe，在不改变 ECMAScript class 行为、重复类定义、AOT、hot patch、GC 和 Sendable 语义的前提下，降低 FunctionTemplate 常驻 shallow bytes。

## 2. 实施范围

### 2.1 纳入范围

- 新版本 ABC 的 class literal 解码；
- 普通 ClassLiteral / LocalHeap；
- Sendable ClassLiteral / SharedHeap；
- static、non-static、constructor、getter、setter、generator、async 和 async-generator 方法；
- property、element 和 accessor 消费路径；
- runtime cache resolve 与 `panda_file_translator.cpp` 预解析入口；
- AOT snapshot method-offset 提取；
- hot patch 对 Method、Module 和 RawProfileTypeInfoCell 的更新；
- heap dump、dump、GC visitor 和对象遍历。

### 2.2 转换门槛

仅当同一 ClassLiteral 含至少 2 个 FunctionTemplate 时启用 compact 表示。单模板和零模板 ClassLiteral 保持旧布局与旧 FunctionTemplate 路径。

转换按单个 ClassLiteral 决定，不使用应用级阈值，不跨 ClassLiteral、ConstantPool、VM 或 heap domain 合并。

### 2.3 非目标

- 不延迟 JSFunction 创建；class definition 仍在原时机创建方法函数；
- 不删除 Method、Module 或 ProfileTypeInfoCell；
- 不改变 ProfileTypeInfoCell 的状态机或 JIT/AOT 策略；
- 不修改 ABC 格式或前端编译器；
- 不引入跨 VM、跨 ConstantPool、跨 LocalHeap/SharedHeap 共享；
- 不将 FunctionTemplate 收益与其他提案相加。

## 3. 数据表示要求

### FR-1 双 ClassLiteral 布局

保留当前 24 B ClassLiteral HClass，用于零/单模板类；新增 compact ClassLiteral HClass，仅用于 `N>=2` 的类。compact ClassLiteral 比旧布局多一个 `Recipes` tagged 字段，object size 为 32 B。

ClassLiteral 创建发生在 literal array 完整解码之后，创建方必须先取得模板计数，再一次性选择旧 HClass 或 compact HClass，不允许先分配后迁移。

### FR-2 literal slot 表示

compact ClassLiteral 的原 literal array 中，每个 FunctionTemplate value slot 改存该模板原有的 Method。property key、非模板 value、trailer、field type、interface type 和数组长度保持原语义。

不得发明新的 JSTaggedValue immediate tag，也不得使用裸指针或外部索引替代 GC 可见引用。

### FR-3 recipe array

compact ClassLiteral 的 `Recipes` 指向同 heap domain 的 TaggedArray。按原 literal 中 Method 出现顺序，每个方法使用三个连续 tagged slot：

1. `Module`；
2. `Length`，以 tagged int 保存原 `uint16_t METHODAFFILIATE`；
3. `RawProfileTypeInfoCell`。

普通 ClassLiteral 使用 LocalHeap recipe；Sendable ClassLiteral 使用 SharedHeap recipe。recipe 不跨域复用，不允许 shared recipe 引用 local object。

### FR-4 一致索引

literal 解码、ClassInfoExtractor、JSFunction 创建、AOT snapshot 和 hot patch 必须使用同一个“按原 literal 顺序递增的 template ordinal”。ordinal 只用于当前 ClassLiteral 内寻址，不能作为跨对象稳定 ID。

compact ClassLiteral 的构建入口必须把 `Recipes` 传给本次 `ClassInfoExtractor`。extractor 在临时 property/element/accessor 数据中为 Method 携带对应 ordinal；属性分类、element 分流和 accessor 合并后，Method 与 ordinal 必须仍成对。该映射只在一次 class definition 内存活，不写回 ClassLiteral，不计入常驻收益；其临时分配和启动开销必须计入性能风险。

新增公共访问器应提供：

- `GetMethod(literalSlot)`；
- `GetModule(ordinal)` / `SetModule(ordinal)`；
- `GetLength(ordinal)`；
- `GetRawProfileTypeInfo(ordinal)` / `SetRawProfileTypeInfo(ordinal)`；
- heap-domain 与边界断言。

业务路径不得直接散布 `ordinal * 3 + field` 算术。

## 4. 行为要求

### FR-5 JSFunction 创建

普通和 Sendable function factory 应新增 recipe 输入路径，使用 Method 的 FunctionKind 选择与现状相同的 function HClass，并恢复 Length 和 Module。HomeObject、LexicalEnv、SFunctionEnv、constructor 及 extensible 处理保持现有顺序。

旧 FunctionTemplate 输入路径保留，供零/单模板类和兼容输入使用。

### FR-6 ProfileTypeInfoCell

普通类创建 JSFunction 时必须从对应 recipe cell slot 读取状态：

- Empty cell 时创建新的 ProfileTypeInfoCell，并同时写回 recipe slot 与 JSFunction；
- 非 Empty cell 时保持现有 `UpdateProfileTypeInfoCellType` 和复用行为；
- multi-context 场景继续禁止模板侧反馈共享，JSFunction 使用 Empty cell，recipe 状态不得被错误升级。

Sendable 路径维持现有共享对象约束，不新增 local cell 引用。

### FR-7 重复类定义

同一 ClassLiteral 多次执行 class definition 时，每次仍创建新的 JSFunction；同一 method ordinal 的 Module、Length 和 feedback anchor 必须来自同一 recipe slot。首次与后续执行的 `function.length`、module、home object、lexical environment 和反馈 cell 语义必须与旧路径一致。

### FR-8 AOT

AOT snapshot 从 compact literal slot 中的 Method 读取 method offset。`IsAOTUsed` 状态、entry index、IHC/CHC 选择和 skipped method 语义保持不变。AOT 路径不得为读取 offset 临时重建 FunctionTemplate。

### FR-9 hot patch

hot/cold patch 必须能遍历 compact ClassLiteral，按 recipe 中 Method 定位目标，并在对应 ordinal 更新 Module；原路径需要重置 feedback 时，同时将 recipe RawProfileTypeInfoCell 重置为 Empty cell。旧 FunctionTemplate visitor 保留用于未转换类。

### FR-10 GC 与发布

- compact ClassLiteral visitor 必须扫描 Array 与 Recipes；
- recipe TaggedArray 由现有 GC visitor 扫描三个 tagged slot；
- LocalHeap 使用本地写屏障；SharedHeap 使用 shared allocation 与 shared 写屏障；
- Sendable ClassLiteral 发布到 ConstantPool 前，literal array 与 recipe 必须全部初始化完成；CAS 失败方不得泄漏或发布半初始化对象；
- snapshot、dump 和 object xray 必须识别两种 ClassLiteral HClass。

## 5. 收益要求

实现后的 clean heap census 必须分别报告：

- FunctionTemplate 真实存量；
- compact 模型覆盖模板数 `N` 和 compact ClassLiteral 数 `C`；
- 删除的 40 B FunctionTemplate bytes；
- recipe array bytes；
- compact ClassLiteral 增量 bytes；
- 条件净 shallow bytes；
- LocalHeap 与 SharedHeap 分域数据；
- committed、RSS、PSS 与 shallow 分开。

基线模型为：

```text
current_bytes = 40 * N
recipe_bytes = 24 * N + 24 * C
conditional_net_shallow = 16 * N - 24 * C
N >= 2 for every converted ClassLiteral
```

任何实现若增加额外 side table、ordinal map、bitmap、HClass、cache 或对象头成本，必须从条件净收益中实扣，不能沿用本基线值。

## 6. 兼容性与回退

- 旧 ClassLiteral 和 FunctionTemplate 类型继续可读、可 dump、可 patch；
- compact 与旧表示可在同一 VM、同一 ConstantPool 中并存；
- 单个 ClassLiteral 不混用两种表示；
- 构建开关只能控制 compact builder 是否启用，关闭后必须完全回到旧表示；
- 不改变 ABC、snapshot 文件或外部调试协议的版本契约，若序列化格式确需变化必须显式升版本并拒绝旧格式误读。
