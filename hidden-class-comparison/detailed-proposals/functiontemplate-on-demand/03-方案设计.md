# FunctionTemplate compact recipe：方案设计

## 1. 设计概览

当前每个 class method 由一个 40 B FunctionTemplate 常驻保存四项状态：

```text
FunctionTemplate = { Method, Module, RawProfileTypeInfoCell, Length }
```

最终实现将其改为 ClassLiteral 级表示：

```text
CompactClassLiteral {
    Array: original literal array, FunctionTemplate value slots replaced by Method
    IsAOTUsed: bool
    Recipes: TaggedArray[
        Module_0, Length_0(Smi), RawProfileTypeInfoCell_0,
        Module_1, Length_1(Smi), RawProfileTypeInfoCell_1,
        ...
    ]
}
```

Method 保留在原 literal slot，避免 recipe 重复引用；其他三项按模板在原 literal 中出现的顺序写入 recipe。没有跨 ClassLiteral interning，也没有全局索引。

## 2. 对象布局

### 2.1 双 HClass

保留现有 ClassLiteral：

```text
TaggedObject header  8 B
Array                 8 B
IsAOTUsed + padding   8 B
--------------------------
SIZE                 24 B
```

新增 compact ClassLiteral HClass：

```text
TaggedObject header  8 B
Array                 8 B
Recipes               8 B
IsAOTUsed + padding   8 B
--------------------------
SIZE                 32 B
```

两者使用同一 JSType，按专用 HClass/object size 判断是否有 Recipes。公共访问器隐藏布局分支，禁止对旧对象读取超出 24 B 的字段。

### 2.2 recipe 成本

TaggedArray 头为 16 B，每模板三个 8 B tagged slot。对 `N` 个模板：

```text
recipe array = 16 + 24N
compact ClassLiteral 增量 = 8
合计 = 24 + 24N
```

只对 `N>=2` 启用，因此每类净收益：

```text
40N - (24 + 24N) = 16N - 24 > 0
```

## 3. 构建路径

### 3.1 literal 解码

`GetDatasIgnoreTypeForClass` 在遇到 METHOD/GETTER/SETTER/GENERATOR/ASYNC-GENERATOR 与后续 METHODAFFILIATE 时，仍创建现有 Method、Module 和 Length，但暂不创建 FunctionTemplate：

1. Method 写入原 FunctionTemplate value slot；
2. Module、tagged Length 和 EmptyProfileTypeInfoCell 追加到临时 recipe builder；
3. 每成功写入一组 triple，template ordinal 加一；
4. 非模板 value、key 和 trailer 保持当前数组格式；
5. 解码结束后，若 `N>=2`，发布 recipe array；若 `N<2`，按旧路径创建 FunctionTemplate，丢弃临时 builder。

`N<2` 的回退在 ClassLiteral 发布前完成，不允许 compact/legacy 混合出现在同一 literal array。

### 3.2 ClassLiteral 创建

`ConstantPool::GetClassLiteralFromCache` 在 literal 解码完成后取得 `{literalArray, recipes, templateCount}`：

- `templateCount < 2`：调用现有 `NewClassLiteral/NewSClassLiteral`；
- `templateCount >= 2`：调用 `NewCompactClassLiteral/NewSCompactClassLiteral`；
- normal 与 Sendable 分别使用 LocalHeap 与 SharedHeap；
- 设置 Array、Recipes、IsAOTUsed 后再发布到 ConstantPool；
- Sendable 继续使用 CAS，失败方对象由 GC 回收，不允许把 local handle 写入 shared recipe。

`panda_file_translator.cpp` 的两个 CLASS_LITERAL 分支必须调用相同 builder/factory，禁止保留第二套布局生成逻辑。

## 4. 消费路径

### 4.1 transient ordinal

`ClassInfoExtractor::BuildClassInfoExtractorFromLiteral` 扫描原 literal array 时维护当前 template ordinal：

- 非 Method value 不递增；
- compact ClassLiteral 的创建入口将 Recipes 引用传给本次 extractor；
- compact literal 的 Method value 生成一个仅在本次 class definition 存活的 `{Method, ordinal}` 关联；
- property、element 和 accessor 的临时 arrays 必须携带同一 ordinal，分类和重排时成对移动；
- extractor 结束后不保留 ordinal side table，不增加常驻成本。

ordinal 使用 tagged int 保存在 extractor 的临时 side array，Recipes 作为 extractor 的临时 tagged 引用。extractor 沿用各入口当前的对象域；Sendable 路径不因本方案把 local extractor 强制迁入 SharedHeap。ordinal side array 与其对应的 property/element 临时数组使用同域分配，所有 local/shared 引用继续满足现有 heap-domain 规则。不能引入 ClassLiteral 生命周期的额外 heap object。该临时数组不计入终态 shallow 收益，但其分配量和启动时延必须在 K9 的关闭证据中单列。

### 4.2 JSFunction 工厂

新增 `CreateJSFunctionFromRecipe` 与 `CreateSFunctionFromRecipe`：

1. 从 literal slot取得 Method；
2. 从 Method 读取 FunctionKind，选择与旧 factory 相同的 function HClass；
3. 从 recipe 读取 Length 和 Module；
4. 设置 JSFunction Length、Module；
5. 由原 helper 设置 HomeObject、LexicalEnv 或 SFunctionEnv；
6. 普通类按 recipe cell slot 执行 feedback anchor 更新。

旧 `CreateJSFunctionFromTemplate/CreateSFunctionFromTemplate` 保留，服务于零/单模板 ClassLiteral 和兼容对象。

### 4.3 feedback anchor

将 `JSFunction::UpdateProfileTypeInfoCell` 的共享逻辑提取为可接受 recipe cell accessor 的内部实现：

- 当前 slot 为 Empty cell：分配 ProfileTypeInfoCell，先写 recipe slot，再写 target JSFunction；
- 当前 slot 为非 Empty cell：执行现有 `UpdateProfileTypeInfoCellType`，再写 target；
- multi-context：保持现状，target 使用 Empty cell，不写 recipe；
- 所有写入使用目标 heap domain 对应的写屏障。

不修改 ProfileTypeInfoCell 对象布局，也不把其潜在节省计入本需求。

### 4.4 accessor 与 element

getter/setter 判断从 Method.FunctionKind 读取，等价于现有 FunctionTemplate helper。所有以下路径都必须同时接受 legacy template 和 compact recipe：

- non-static properties；
- static properties；
- dictionary properties；
- numeric elements；
- AccessorData getter/setter；
- Sendable accessor 与 elements。

## 5. AOT 与 patch

### 5.1 AOT snapshot

`snapshot_constantpool_data.cpp` 当前从 FunctionTemplate.Method 提取 offset。compact 路径直接识别 Method 并读取 MethodId；legacy 分支保留。method traversal 顺序和 `NO_FUNC_ENTRY_VALUE` 对齐不得变化。

IHC/CHC、`IsAOTUsed`、entry index 和 skippedMethods 不存入 recipe，也不计入收益。

### 5.2 hot/cold patch

patch loader 增加 compact ClassLiteral visitor：

1. 扫描 literal array 中的 Method；
2. 使用同一 template ordinal 找到 recipe triple；
3. 按 MethodId/JSPandaFile 定位 patch；
4. 修改对应 Module；
5. 热补丁路径将对应 RawProfileTypeInfoCell 重置为 Empty cell；
6. cold patch 按当前 `hasModule` 规则写 Module 或 Undefined。

不能只更新已实例化 JSFunction；否则后续重复 class definition 会从旧 recipe 创建错误函数。

## 6. GC、并发与可观测性

### 6.1 GC

- 旧 ClassLiteral visitor 不变；
- compact ClassLiteral visitor 扫描 Array 和 Recipes；
- recipe 使用 TaggedArray 原生 visitor；
- Method、Module、cell 都是强引用，与原 FunctionTemplate 一致；
- Length 为 tagged int，不形成堆引用；
- heap dump 为 compact ClassLiteral 输出 Array、Recipes 和 ordinal 字段名，便于 owner 复算。

### 6.2 并发发布

普通 ClassLiteral 在当前线程完整初始化后写 ConstantPool。Sendable ClassLiteral 使用 shared old-space objects，Array 与 Recipes 都必须在 CAS 前完成初始化。发布后允许的 recipe 写只有 Module 与 RawProfileTypeInfoCell 对应槽，必须沿用 shared barrier 和当前 FunctionTemplate 路径的同步约束。

不允许 LocalHeap recipe 引用 SharedHeap ClassLiteral 的可变状态，也不允许 SharedHeap recipe 引用 LocalHeap Method、Module 或 cell。

### 6.3 dump 与诊断

heap dump 需要区分：

- legacy FunctionTemplate；
- compact ClassLiteral；
- recipe array；
- Method/Module/Length/RawProfileTypeInfoCell ordinal 关系。

诊断字段只用于 dump，不新增运行时 name string 或 per-object debug metadata。

## 7. 收益

### 7.1 真实存量

Top13 共有 954,059 个 FunctionTemplate，真实 shallow 36.394 MiB。快手前台为 57,864 / 2.207 MiB，后台为 55,523 / 2.118 MiB。

### 7.2 模型覆盖与条件净值

| 样本 | 覆盖模板 `N` | compact 类 `C` | 被替换对象 | recipe 与类增量 | 条件净 shallow |
|---|---:|---:|---:|---:|---:|
| Top13 汇总 | 913,819 | 119,627 | 34.859 MiB | 23.654 MiB | 11.206 MiB |
| 快手前台 | 54,918 | 7,176 | 2.095 MiB | 1.421 MiB | 0.674 MiB |
| 快手后台 | 52,700 | 6,885 | 2.010 MiB | 1.364 MiB | 0.647 MiB |

Top13 汇总仅用于说明跨样本容量，不是单进程承诺。实现若新增额外元数据，必须从上表净值实扣。

### 7.3 不可声称的收益

- 不能把 36.394 MiB FunctionTemplate 存量全部写成净收益；
- 不能使用旧 `40%–70% never-instantiated` 假设；
- 不能把前台与后台相加；
- 不能由 shallow 推导 committed、RSS 或 PSS；
- 不能叠加 ProfileTypeInfoCell、LayoutInfo、ConstantPool、Interop 或编译期 DCE 收益。

## 8. 风险与关闭证据

| ID | 风险 | 影响 | 方案内缓解 | 关闭证据 |
|---|---|---|---|---|
| K1 | literal scan、属性重排与 recipe ordinal 漂移 | 方法绑定到错误 Module/Length/Cell，直接产生语义错误 | builder、extractor、AOT、patch 共用 ordinal helper；Method/ordinal 在临时 arrays 中成对移动；边界断言 | static/non-static/element/getter/setter/constructor/async/generator 的 ordinal 对照测试；dump 中每 ordinal MethodId 与旧版一致 |
| K2 | `N<2` 回退出现混合表示 | 旧消费者误读 Method 为 FunctionTemplate | 发布前一次性选择 legacy 或 compact；单 ClassLiteral 禁止混用 | 零/单/双模板单测；heap census 证明每 ClassLiteral 仅一种表示 |
| K3 | multi-context 错误共享 feedback | 跨 context 污染反馈状态 | 保留现有 multi-context 分支，不更新 recipe cell | multi-context 重复 class definition 对照，recipe 保持 Empty，JSFunction cell 行为与旧版一致 |
| K4 | Sendable recipe 出现 local 引用或发布竞态 | SharedHeap 崩溃、GC 错误、数据竞争 | shared factory、同域断言、CAS 前全初始化、shared barrier | shared heap validator、TSAN/并发重复定义、CAS 竞争和 shared GC 压测无错误 |
| K5 | hot patch 只更新 legacy template 或已创建函数 | 后续类定义恢复旧 Module/Cell | patch visitor 同时覆盖 compact ClassLiteral，按 Method+ordinal 更新 | hot/cold patch 后再次执行 class definition，Module、行为和 cell reset 与旧版一致 |
| K6 | AOT method offset 顺序变化 | entry index、IHC/CHC 错配 | compact slot直接保存 Method；沿用原 traversal 顺序 | clean AOT build；snapshot methodOffsetVec 与旧版逐项一致；AOT class tests 全过 |
| K7 | GC visitor 或 object size 配置错误 | 漏扫、越界扫描、堆损坏 | 两个专用 HClass/object size；compact visitor 扫描 Array+Recipes | full/minor/shared GC stress、heap verifier、ASAN、dump/xray 遍历无异常 |
| K8 | translator 旁路仍创建 FunctionTemplate | AOT/预解析场景收益缺失或混合表示 | runtime cache 与 translator 共用 builder | 两个 translator CLASS_LITERAL 分支对象 census 与 runtime resolve 一致 |
| K9 | hot path增加 ordinal side array 分配与访问 | class definition 启动时延和瞬时分配回退 | 单次线性构建，不做 Method 反查或全局查表；extractor 销毁后释放 | 同场景 class-definition microbenchmark 与应用启动 trace；单列 transient allocated bytes、P50/P95，无不可接受回退 |
| K10 | recipe array 碎片或 committed 不降 | shallow 减少但物理收益不兑现 | 仅 `N>=2` 启用；单类净收益为正；同域连续数组 | clean A/B 的 heap committed、RSS、PSS 分项；无 shallow 到 PSS 换算 |
| K11 | dump schema 无法复算 owner/成本 | 后续收益不可审计 | 输出 compact ClassLiteral、recipe 和 ordinal 边 | 新快照用本目录脚本复算，template owner、N、C、recipe bytes 与运行时计数一致 |
| K12 | 旧 snapshot/序列化误读新布局 | 加载失败或静默错误 | 不改变外部格式；若确需持久化新对象则显式升版本 | 新旧产物双向兼容矩阵；不兼容输入明确拒绝，不静默 fallback |
