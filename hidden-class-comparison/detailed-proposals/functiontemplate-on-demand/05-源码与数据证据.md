## 2. 对象布局

### 2.1 FunctionTemplate

`ecmascript/js_function.h:732-760`

- `FunctionTemplate` 继承 `TaggedObject`；
- `Method`：`js_function.h:753-754`；
- `Module`：`js_function.h:754-755`；
- `RawProfileTypeInfo`：`js_function.h:755-756`；

15 份快照中 FunctionTemplate self_size histogram 均只有 `40`。

### 2.2 ClassLiteral

`ecmascript/jspandafile/class_literal.h:26-36`

- `Array` 是唯一 tagged 字段：`class_literal.h:30-32`；
- `IsAOTUsed` 紧随其后：`class_literal.h:32-35`；
- visitor 只扫描 Array：`class_literal.h:36`。

快照中的现有 ClassLiteral shallow size 为 24 B。compact HClass 新增一个 8 B Recipes tagged 字段后模型为 32 B。

### 2.3 TaggedArray

`ecmascript/tagged_array.h:80-84,126-130`

- `ComputeSize = DATA_OFFSET + elemSize * length`；
- `Length` 与 `ExtraLength` 构成 16 B array header；
- tagged slot 为 8 B。

因此三槽 recipe array 成本为 `16 + 24N`。

## 3. 创建路径

### 3.1 literal decode

`ecmascript/jspandafile/literal_data_extractor.cpp:241-285`

- `DefineFunctionTemplate` 接收 method offset、constant pool、FunctionKind、Length、AOT entry、Sendable env 和 ClassKind；
- Method 创建：`literal_data_extractor.cpp:254-267`；
- Module 生成：`literal_data_extractor.cpp:269-275`；
- Sendable/normal 模板分流：`literal_data_extractor.cpp:278-284`。

`ecmascript/jspandafile/literal_data_extractor.cpp:586-624`

- METHOD/GETTER/SETTER/GENERATOR/ASYNC-GENERATOR 先记录 method id/kind；
- METHODAFFILIATE 提供 `uint16_t length`：`611-612`；
- 随后创建 FunctionTemplate 并写入 literal array：`621-624`。

Length 来自 ABC METHODAFFILIATE，不能由 Method 参数个数无损替代。

### 3.2 LocalHeap factory

`ecmascript/object_factory.cpp:5582-5594`

- 分配 FunctionTemplate；
- 写入 Method、Module、EmptyProfileTypeInfoCell 和 Length。

### 3.3 SharedHeap factory

`ecmascript/shared_object_factory.cpp:610-622`

- `NewSFunctionTemplate` 在 SharedHeap 分配同一 FunctionTemplate HClass；
- 写入同样四个字段。

shared tagged array factory：`shared_object_factory.cpp:483-506,804-816`。本方案使用该现有同域分配能力，不跨 heap domain 共享 recipe。

### 3.4 ClassLiteral cache

`ecmascript/jspandafile/program_object.cpp:20-64`

- cache miss 后先完整生成 literal array：`43-44`；
- 之后才按 ClassKind 创建 ClassLiteral：`45-50`；
- 设置 Array 后发布到 ConstantPool：`51-60`；
- Sendable 使用 CAS：`53-54`。

该顺序允许在 ClassLiteral 分配前取得 template count，并直接选择 legacy 或 compact HClass。

### 3.5 translator 旁路

`ecmascript/jspandafile/panda_file_translator.cpp:251-257,322-328`

两个 CLASS_LITERAL 分支均直接生成 literal array、`NewClassLiteral`、`SetArray`。正式实现必须与 runtime cache 使用同一 compact builder。

## 4. 消费与状态

### 4.1 Function factory

`ecmascript/object_factory.cpp:726-776`

- normal 与 Sendable factory 都从 FunctionTemplate.Method 的 FunctionKind 选择函数 HClass；
- normal 在 `748-752` 读取 Method、Length、Module；
- Sendable 在 `771-775` 读取相同字段。

compact recipe 能提供同样输入，不需要改变 JSFunction 布局。

### 4.2 class definition

`ecmascript/jspandafile/class_info_extractor.cpp:422-604`

- static/non-static property 遇到 FunctionTemplate 会立即创建 JSFunction；
- `ClassHelper::CreateJSFunctionFromTemplate` 调用 factory 后处理 multi-context 和 feedback cell：`592-608`。

Sendable 路径：`class_info_extractor.cpp:794-952`。

- Sendable property/element/accessor 同样识别并消费 FunctionTemplate；
- `CreateSFunctionFromTemplate` 设置 HomeObject 和 SFunctionEnv：`940-952`。

因此 FunctionTemplate 不是“方法调用前未实例化对象”；class definition 首次执行已经消费模板。

### 4.3 ProfileTypeInfoCell

`ecmascript/js_function.cpp:1208-1223`

- 从 FunctionTemplate 读取 RawProfileTypeInfoCell；
- Empty 时分配 cell，并写回模板与新 JSFunction：`1214-1219`；
- 非 Empty 时升级类型并复用到新 JSFunction：`1220-1222`。

该字段是同一 ClassLiteral 重复执行时的 feedback anchor，不能删除或每次重建。

### 4.4 Runtime class entry

`ecmascript/stubs/runtime_stubs-inl.h:1004-1066`

- normal class 从 cache 取得 ClassLiteral 与 Array；
- BuildClassInfoExtractor 后定义 class；
- class method JSFunction 在同一次 class definition 中创建。

Sendable entry：`runtime_stubs-inl.h:1105-1139`，同样从 ClassLiteral.Array 构建 extractor。

## 5. AOT、patch、GC

### 5.1 AOT snapshot

### 6.2 owner 规则

对每个 ClassLiteral：

1. 读取名为 `Array` 的出边；
2. 遍历该 array 直接指向的 FunctionTemplate；
3. 对 target object identity 去重；
4. 要求所有模板恰有一个 ClassLiteral owner；
5. `N>=2` 的类进入模型；单模板类保持旧表示。

所有 15 份输入均满足：unowned = 0，multiply-owned = 0，模板尺寸统一 40 B。
