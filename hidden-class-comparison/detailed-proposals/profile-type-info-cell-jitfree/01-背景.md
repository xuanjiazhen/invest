# ProfileTypeInfoCell JIT-free 裁剪 —— 背景

本文件存放理解本方案所需的背景知识与现有实现介绍。

## 1. ProfileTypeInfoCell 是什么

`ProfileTypeInfoCell` 是 ArkVM 的 **IC 类型反馈单元**：解释器在属性访问、调用等反馈路径分配它，通过 `JSFunction::RawProfileTypeInfo` 关联，承载类型反馈（`Value` 指向 `ProfileTypeInfo`）与 JIT 机器码弱缓存（`MachineCode`）。

## 2. 当前布局（32 B）

源码：`ecmascript/ic/profile_type_info_cell.h`。

| 偏移 | 大小 | 字段 | 语义 |
|---:|---:|---|---|
| 0 | 8 B | `TaggedObject` header | 对象头 |
| 8 | 8 B | `Value` | `ProfileTypeInfo` 或空值（**解释器/IC/PGO/AOT 读取**） |
| 16 | 8 B | `MachineCode` | JIT `MachineCode` **弱引用**缓存或 `Hole` |
| 24 | 8 B | `Handle` | profiler 使用的 cell 状态 |
| **合计** | **32 B** | `ProfileTypeInfoCell::SIZE` | |

创建时初始化：`Value=创建参数`、`MachineCode=Hole`、`Handle=Undefined`。

## 3. 两类关键机制（背景知识）

### 3.1 解释器 IC 反馈路径（cell 的核心用途）

```
JSFunction::RawProfileTypeInfo
  → ProfileTypeInfoCell::Value
  → ProfileTypeInfo
```

- 函数创建时 `RawProfileTypeInfo = EmptyProfileTypeInfoCell`（单例哨兵，`js_function.cpp:112`）；
- 解释器反馈路径（`interpreter-inl.cpp:1046-1063`）在 profile slot 未建立时 `NewProfileTypeInfoCell` 分配独立 cell；
- 属性访问 IC、操作类型反馈、类定义反馈、PGO 数据均通过 `Value` 读取，**不依赖 `MachineCode` 槽**。

### 3.2 MachineCode 槽的生产与消费（JIT 专用）

```
JitTask::InstallCode
  → JSFunction::SetJitMachineCodeCache
  → ProfileTypeInfoCell::SetMachineCode(weak MachineCode)
```

- deopt 路径将该槽写回 `Hole`（`deoptimizer.cpp:684`）；
- runtime 诊断读取该槽输出机器码弱引用状态（`runtime_stubs.cpp:4878`）；
- 该槽是**弱引用**缓存，GC 处理弱 MachineCode。
- 仓库级消费者仅上述三类（安装 / deopt 清理 / 诊断），全部位于 JIT 能力闭包内。

### 3.3 Handle 槽的生产与消费（PGO 专用）

```
ProfilerStubBuilder::ProfileDefineClass（compiler/profiler_stub_builder.cpp:155，写 weakCtor）
PGOProfiler（pgo_profiler/pgo_profiler.cpp:1338，读 Handle）
ObjectFactory / SharedObjectFactory 初始化（object_factory.cpp:5560、shared_object_factory.cpp:597）
```

Handle 的运行时消费者只有 **PGO 采集链路**：profiler stub 把类定义反馈以 weak 引用写入 Handle，PGOProfiler 序列化时读取。IC、AOT 执行、解释器均不读写该槽。因此在「编译期 PGO 也不使能」的产品变体中，Handle 槽与 MachineCode 槽同为可裁剪槽。

### 3.4 两个 MachineCode 字段的边界

`JSFunction::MachineCode`（函数本体的 JIT 产物强引用）有独立消费者（JIT 入口/deopt/栈回溯/调试），**不在本方案范围**。本方案只处理 `ProfileTypeInfoCell::MachineCode`（cell 内的 JIT 弱缓存槽）。

## 4. cell 的分配时机：DEFINEFUNC 即时分配与惰性空间

`ProfileTypeInfoCell` 在 **DEFINEFUNC 指令执行时即分配**，与被定义函数是否收集过反馈无关：

| 路径 | 位置 |
|---|---|
| 解释器 C++（DEFINEFUNC_IMM8/IMM16 handler） | `interpreter/interpreter-inl.cpp:1046-1063`（`UpdateProfileTypeInfoCellToFunction`），调用点 `:5106/:5132` |
| 生成代码（DefineFunc stub） | `new_object_stub_builder.cpp:1453`、`interpreter_stub-inl.h:576`、`stub_builder.cpp:12472`、`circuit_builder.cpp:1619` |
| FunctionTemplate 实例化 | `js_function.cpp:1211-1223`（`UpdateProfileTypeInfoCell`） |

惰性分配的机制基础（均已源码核验存在）：

- 函数出生时 `RawProfileTypeInfo` 本就是 `EmptyProfileTypeInfoCell` 单例哨兵（`js_function.cpp:112`）；
- `JSFunction::SetProfileTypeInfo`（`js_function.cpp:1199-1205`）已实现「Empty → 按需分配 cell」的运行时转换；
- Top13 实测 9.9‰ 之外的 99.9% cell 停留 `cell_0`（Value=Undefined，从未承载反馈）——绝大多数 cell 是纯驻留开销。

业界先例：V8 lazy feedback vector allocation（反馈结构延迟到预热后分配，冷函数零反馈驻留）。本方案将其与裁槽合并为同一详细方案的两个阶段（先惰性缩小基数、后裁槽缩小尺寸）。

## 5. 编译期能力与「JIT-free 变体」

- 当前 JIT/AOT 是运行时选项（`OPTION_COMPILER_ENABLE_JIT`）；
- 产品分档规划：≤6G 内存设备通过宏编译关闭 AOT 与 JIT，形成编译期确定的低档变体；
- 该变体不编译 Fast JIT、Baseline JIT、OSR、JIT deopt 及依赖 cell 机器码缓存的诊断分支；
- **双层能力闭包**（方案层命名，落地时由目标 revision 已有 GN feature 汇总生成）：

```text
ARK_PROFILE_CELL_HAS_MACHINE_CODE = FAST_JIT_ENABLED || BASELINE_JIT_ENABLED
                                    || OSR_ENABLED || JIT_DEOPT_ENABLED
                                    || JIT_CODE_DIAGNOSTICS_ENABLED
ARK_PROFILE_CELL_HAS_HANDLE       = PGO_PROFILER_ENABLED
```

- 三档布局：全能力 32 B；无 JIT 有 PGO 24 B；无 JIT 且无 PGO（≤6G 档的目标形态，**待产品确认 PGO 随 AOT 一并关闭**）16 B。

## 6. Top13 数据

- 快照记录 935,138 个 `profile_type_info_cell_0`（占 99.9%），`cell_1`/`cell_n` 仅数百个；
- cell_0 是「未收集到反馈」状态，但 **cell 本身由解释器反馈路径分配**（`interpreter/interpreter-inl.cpp:1046-1063`）——「JIT-off 就无用途」不成立，cell 不能删除，只能裁剪 JIT/PGO 专用槽。
