# ProfileTypeInfoCell 惰性分配与 JIT-free 裁剪 —— 方案设计（按架构特性设计模板）

## 1、特性需求/问题/动机的来源与价值

**问题来源（两块存量）**：

1. **数量问题**：cell 在 DEFINEFUNC 指令执行时即分配（`interpreter-inl.cpp:1046-1063` 及生成代码 4 处、`js_function.cpp:1211-1223`，共 7 处），Top13 观测 935,138 个 cell 中 99.9% 停留 `cell_0`（Value=Undefined，从未承载反馈）——绝大多数为纯驻留开销；
2. **尺寸问题**：`MachineCode` 槽是 JIT 机器码弱缓存（消费者：JIT 安装 `jit_task.cpp:388`、deopt 清理 `deoptimizer.cpp:684`、运行时诊断 `runtime_stubs.cpp:4878`），`Handle` 槽是 PGO 采集专用（消费者：profiler stub 写入 `profiler_stub_builder.cpp:155`、PGOProfiler 读取 `pgo_profiler.cpp:1338`）。在编译期确定无 JIT（≤6G 分档宏编译关闭 AOT/JIT）且 PGO 随 AOT 一并关闭的产品变体中，两槽均无消费者。

**价值**（组合模型，e=惰性消除率）：`N×(32e + tier(1−e)) B`——e=0.8 时惰性+16 B 档组合收益 25.6 MiB（绝对上界 28.5）。阶段一（惰性）为 V8 lazy feedback vectors 的等价迁移，全档位通用、无产品依赖、可独立交付。

**实现前 vs 实现后**：实现前每个被定义函数即时持有 32 B cell（其中 99.9% 终身无反馈，JIT-free 构建还带无用机器码槽）；实现后未收集反馈的函数持有 Empty 哨兵（零增量），收集过反馈的函数按档位持有 32/24/16 B cell，反馈协议不变。

## 2、特性影响分析

### 2.1 系统位置

ProfileTypeInfoCell 位于 IC 反馈链路（JSFunction → RawProfileTypeInfo → cell → ProfileTypeInfo），同时被 JIT 安装路径（`JitTask::InstallCode → SetJitMachineCodeCache`）和 profiler 使用。本方案触碰该链路的三个环节：分配时机（DEFINEFUNC → 首次反馈触发）、cell 自身布局（三档）、消费闭包（JIT/PGO 条件编译）。不改 JSFunction 布局（冻结硬约束不受影响）。

### 2.2 环境依赖

- 双层编译期能力闭包：`ARK_PROFILE_CELL_HAS_MACHINE_CODE`（由 FAST/BASELINE/OSR/JIT_DEOPT/JIT_DIAGNOSTICS 汇总）、`ARK_PROFILE_CELL_HAS_HANDLE`（由 PGO 汇总，方案层命名，落地时由既有 GN feature 生成）；
- 三档尺寸仅由上述闭包取值决定；多 target/多 OS 无差异。

### 2.3 涉及模块

`ic/profile_type_info_cell.h`、`object_factory`、`shared_object_factory`（shared Empty cell）、compiled `NewProfileTypeInfoCell` stub（含 `interpreter_stub` 生成路径）、JIT 安装/deopt/诊断（条件编译）、PGO profiler stub 与 `pgo_profiler`（16 B 档条件编译）、GC visitor/xray、serializer/snapshot/AppSpawn、hprof/rawheap/debugger/profiler、`js_metadata_test`。

### 2.4 前后版本兼容性

- 不改变字节码格式、公开 API、JSFunction 布局、反馈协议；
- cell offset 是内部契约：`ARK_PROFILE_CELL_HAS_MACHINE_CODE` 纳入构建 feature fingerprint；snapshot/AOT/AI 版本检查覆盖；24 B 与 32 B 产物双向稳定拒绝；禁止 OTA 只更 runtime 保留旧 snapshot。

### 2.5 外部用户感知

无（反馈协议、Empty 哨兵、cell 状态转换语义不变）。

### 2.6 性能影响

- 时间：解释器/IC/PGO 路径不变（读 `Value` 不读 `MachineCode`）；GC 扫描区间减一个槽；
- 空间：每 cell -8 B；需验证 allocator 实际粒度（24 B 不得取整到 32 B）。

## 3、业界竞品分析

| 引擎 | 对应结构 | 做法 |
|---|---|---|
| V8 | FeedbackVector | **惰性分配**（lazy feedback vectors，预热后才分配）+ 反馈与代码缓存分离 |
| JSC | 内联缓存槽 | 代码对象由函数持有 |
| ArkVM（本方案） | ProfileTypeInfoCell | 阶段一迁移 V8 惰性分配语义；阶段二按编译期档位裁剪 JIT/PGO 专用槽 |

V8 的惰性反馈向量是其降内存的成熟措施（冷函数零反馈驻留），本方案阶段一即其等价迁移——且 ArkVM 的 Empty 哨兵与 Empty→cell 转换机制已存在，迁移成本低；阶段二进一步对剩余 cell 按档位裁槽。

## 4、本特性的设计/实现方案

### 4.1 阶段一：惰性分配（全档位通用）

**分配点删除（7 处）**：

| 位置 | 改动 |
|---|---|
| `interpreter-inl.cpp:1046-1063` | `UpdateProfileTypeInfoCellToFunction` 删除「slot 为 Undefined 即分配」分支；slot 已有 cell 时沿用（共享计数） |
| `interpreter-inl.cpp:5106,5132` | DEFINEFUNC handler 仅保留复用路径 |
| 生成代码 4 处（`new_object_stub_builder.cpp:1453`、`interpreter_stub-inl.h:576`、`stub_builder.cpp:12472`、`circuit_builder.cpp:1619`） | 同步删除 `TaggedIsUndefined(slotValue) → NewProfileTypeInfoCell` 分支 |
| `js_function.cpp:1211-1223` | `UpdateProfileTypeInfoCell`（template 路径）仅复用不新建 |

**首触发路径（复用既有机制，不新增状态）**：

- 反馈写入遇 `RawProfileTypeInfo == Empty` → `SetProfileTypeInfo`（`js_function.cpp:1199-1205`）的 Empty→cell 分支即分配点；
- PGO define-class：profiler stub 需向 slot 内 cell 写 Handle——**PGO 开启的构建保留 DEFINEFUNC 即时分配**（条件分支），或 stub 遇 Undefined 先经 runtime 分配；两形态二选一在实现时冻结，DT 覆盖两形态；
- IC 读取遇 Empty：行为等同现状「未预热」（Empty 是函数出生态，读取链已处理）。

**语义保持**：cell_0→1→N 共享计数只作用于已分配 cell；计数起点从「首个同 slot 闭包」推迟到「首个分配触发」，数值等价。JIT 编译候选遇 Empty 视为「无反馈不可编译」，与现状未预热一致（V8 同型行为）。

**不采用阈值触发**（ADR 结论）：Empty 读取代价仅一次分支，无需 V8 式 interrupt budget 与阈值调参；「何时需要反馈」由反馈系统首写自决。

### 4.2 阶段二：目标布局（三档，由能力闭包决定）

```text
全能力（32 B）:  header + Value + MachineCode + Handle
JIT-free（24 B）: header + Value + Handle
JIT-free + PGO-free（16 B，≤6G 档目标形态）: header + Value
```

24 B 档约束：`VALUE_OFFSET=8`、`HANDLE_OFFSET=16`、`SIZE=24`；16 B 档约束：`VALUE_OFFSET=8`、`SIZE=16`。访问器按编译期能力展开（`#if ARK_PROFILE_CELL_HAS_MACHINE_CODE` / `#if ARK_PROFILE_CELL_HAS_HANDLE` 决定是否定义对应 accessor），布局由单一头文件常量决定，禁止 factory/stub/GC/工具各自计算尺寸。

### 4.3 通用布局（JIT-enabled 32 B）

`header + Value + MachineCode + Handle = 32 B`，行为不变。`CELL_0/1/N` 三类 HClass 在同一构建统一使用当前 `SIZE`；`UpdateProfileTypeInfoCellType` 只改 HClass 状态不改实例尺寸。

### 4.4 条件编译范围

只在 `ARK_PROFILE_CELL_HAS_MACHINE_CODE=true` 时声明/编译：`JSFunction::SetJitMachineCodeCache`、cell `Get/SetMachineCode`、deopt 对 cell 机器码缓存的清理、runtime 诊断输出。

只在 `ARK_PROFILE_CELL_HAS_HANDLE=true` 时声明/编译：cell `Get/SetHandle`、`ProfilerStubBuilder` 写 Handle 的分支（`profiler_stub_builder.cpp:155` 一带）、`PGOProfiler` 对 Handle 的读取（`pgo_profiler.cpp:1338`）。

JIT-free/PGO-free 变体**不提供空实现**——残留消费者直接构建失败，作为能力闭包的静态校验。

### 4.5 保留的反馈路径（不得添加档位特判）

`JSFunction::Get/SetProfileTypeInfo`、`UpdateProfileTypeInfoCellToFunction`、`RuntimeNotifyInlineCache`、interpreter/汇编解释器 `Value` 加载、`UpdateProfileTypeInfoCellType`、PGO profiler `Value` 读取（24 B 档）。`Handle` 的 profiler 读写仅存在于 32/24 B 档构建。

### 4.6 方案利弊

| 方案 | 优点 | 代价 |
|---|---|---|
| **阶段一：首写触发惰性分配（选）** | 消除率×28.5 MiB；机制现成（Empty→cell 已存在）；全档位通用、独立交付 | 反馈首写路径多一次 Empty 判断；PGO 需条件保留 |
| 阈值触发（否决） | — | 需新增计数与检查点，收益与首写触发相同 |
| **阶段二：编译期三档布局裁剪（选）** | 收益确定（-8B/-16B per cell）；静态校验残留消费者 | 依赖编译期能力闭包与产品分档冻结 PGO 决策 |
| 运行时 `--jit=false` 切换布局（否决） | 无需多档布局 | 同一镜像两种尺寸混堆，visitor/metadata 无法区分 |

实施顺序：阶段一先行（约 30 人日独立交付，收益 e×28.5 MiB）；阶段二在阶段一基线上按档位裁剪剩余 (1−e) 存量。

## 5、DFX 分析

- 可诊断性：JIT-free heap dump 中 cell `self_size` 与档位一致（24/16 B）、无 `MachineCode` 边（16 B 档亦无 `Handle` 边）；dump 输出逻辑字段；
- 可运维性：feature fingerprint + 版本双向拒绝；
- 可测试性：见第 7 节。

## 6、可信分析

- **可靠性**：GC 按目标尺寸边界遍历、compaction 不越界、哨兵对象压力验证；弱引用处理器不再收到 cell MachineCode 槽（32 B 档除外）；
- **安全性**：不涉及；**隐私/无害**：不涉及（内部布局改造）。

## 7、关键 DT 用例简述

| 测试用例名称 | 预置条件 | 用例关键步骤 | 预期结果 |
|--------------|----------|--------------|----------|
| 惰性后快照对账 | 阶段一构建 | 插桩消除率 vs cell 节点数下降量 | 数值一致 |
| 首反馈触发分配 | 阶段一构建 | 定义函数→执行至首个 IC 写入 | Empty→cell 转换一次，后续复用 |
| 同 slot 多闭包共享计数 | 阶段一构建 | 同 slot 定义两个闭包并均触发反馈 | 单 cell，计数从分配点起算等价 |
| PGO 构建保留即时分配 | 阶段一+PGO | define-class profiling | Handle 采集不缺失 |
| JIT-free 构建静态校验 | JIT-free 配置 | 全仓扫描 MACHINE_CODE_OFFSET/SetMachineCode | 引用数 0 |
| 16 B 档静态校验 | JIT-free+PGO-free 配置 | 全仓扫描 HANDLE_OFFSET/SetHandle/GetHandle | 引用数 0 |
| 目标尺寸 allocator 粒度 | JIT-free + Interpreter | 压力分配 cell 后检查 Region 占用 | 实际占用按 24/16 B 下降，无对齐取整 |
| 各档位产物互拒 | 两套构建 | 24/16 B runtime 加载 32 B snapshot | 稳定拒绝 |
| IC 反馈回归 | JIT-free | 属性 load/store UNINIT→MEGA 转换 | Value/Handle 语义不变 |
| 哨兵边界 | 目标尺寸 cell 后放哨兵对象 | 压力 GC | 哨兵内容不变 |
| PGO 回归（24 B 档） | JIT-free+PGO | 类定义反馈 dump/merge | Handle 读写语义不变 |
| JIT-enabled 32 B 回归 | Fast/Baseline JIT | 安装弱缓存 + deopt 清理 | 行为不变 |

## 8、结论

方案设计完成，按「阶段一惰性分配（全档位）→ 阶段二三档裁剪（编译期能力闭包）」实施；阶段一可独立交付。遗留问题见 `04-review-log.md`。
