# ProfileTypeInfoCell 编译期裁槽 —— 需求

本文件描述 `ProfileTypeInfoCell` 的两个编译期裁槽阶段。

## 1. 方案目标（两阶段）

**阶段一：JIT-free 裁槽（确定实施项）**——面向编译期确定不包含 JIT 能力的产品变体，删除 cell 的 `MachineCode` tagged 槽，使 cell 从 32 B 缩减为 24 B。保留 `Value`、`Handle`、Empty 哨兵和全部 cell 分配/共享行为。

**阶段二：JIT-free + PGO-free 裁槽（条件实施项）**——仅当编译期同时确定不包含 PGO 采集能力时，再删除 `Handle`，使 cell 从 24 B 缩减为 16 B。PGO 可以在没有 AOT 时独立采集并保存 `.ap`，因此 AOT-free 不等于 PGO-free；不能用 AOT 开关代替本阶段的 PGO 能力闭包。

实施顺序：阶段一可独立交付；阶段二在产品冻结 PGO-free 构建并证明 Handle 消费者闭包清零后启用。两个阶段均不改变 cell 数量。

### 1.1 备选路线：字段外存（通用构建统一 16 B）

裁槽两阶段只作用于能力闭包档位；备选路线将 `MachineCode`（per-VM 双弱关系表）与 `Handle`（堆外 PGO 会话表）外存，使通用构建同样得到 16 B cell（`16N`：前台 1.037 MiB / 后台 0.881 MiB，另计 ≤2 MiB 表成本与 profiler 记录路径的 runtime 调用）。≤6G 档两路线收益等价、裁槽更简单，维持裁槽首选；设计与取舍见 03-方案设计 §4.7。

## 2. 收益

设 `N` 为基线快照中全部现存 cell 数量，`CELL_0/1/N` 均使用同一布局并全部计入：

| 阶段 | 目标布局 | 单 cell 收益 | 总收益公式 |
|---|---:|---:|---:|
| 阶段一：JIT-free | 24 B | 8 B | `8N` |
| 阶段二：JIT-free + PGO-free | 16 B | 累计 16 B | `16N` |

历史 Top13 只冻结了 935,138 个 `CELL_0`，可用于计算裁槽收益下界：阶段一至少 7,481,104 B（7.135 MiB），阶段二累计至少 14,962,208 B（14.269 MiB）。该下界不含 `CELL_1/N`，也不把 `CELL_0` 解释为未反馈状态。

**硬性前提**：目标尺寸必须对应实际对象尺寸和有效分配粒度。ArkVM young/old 空间按 8 B 对齐 bump 分配，16/24 B 预期可兑现；正式放行仍须核验 Region 实际占用，若被额外 padding 或其他成本抵消则不产品化。

### 2.1 快手前后台收益对账

| 指标/阶段 | 前台 | 后台 full-GC | 计算口径 |
|---|---:|---:|---|
| 基线 cell 总数 `N` | 67,940 | 57,714 | `CELL_0 + CELL_1 + CELL_N` |
| 基线 cell 浅层堆 | 2,174,080 B（2.073 MiB） | 1,846,848 B（1.761 MiB） | `32N` |
| 阶段一：24 B 总收益 | 543,520 B（0.518 MiB） | 461,712 B（0.440 MiB） | `8N`，删除 `MachineCode` |
| 阶段二：16 B 累计总收益 | 1,087,040 B（1.037 MiB） | 923,424 B（0.881 MiB） | `16N`，再删除 `Handle` |
| 阶段二相对阶段一增量 | 543,520 B（0.518 MiB） | 461,712 B（0.440 MiB） | 额外 `8N` |
| 16 B 后 cell 浅层堆 | 1,087,040 B（1.037 MiB） | 923,424 B（0.881 MiB） | `16N`，较基线下降 50% |

上述收益是对象布局逻辑字节，不含 `ProfileTypeInfo`、`JSFunction`、Region 空洞和 committed/resident 变化。浅层堆下降不等于 Region committed、峰值 RSS 或 PSS 同额下降，物理内存必须通过同设备、同构建、同场景 clean A/B 验收，不设固定折算系数。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| cell 尺寸被分配器取整抵消 | 中 | 核验 `SIZE`、allocator 实际字节和 Region used；无实际下降则不产品化 |
| 16/24/32 B 多档布局混用 | 高 | 同一镜像只允许一种尺寸；编译期能力闭包决定，运行时开关不能切换；档位纳入构建 feature fingerprint |
| 残留 `MACHINE_CODE_OFFSET`/`HANDLE_OFFSET` 消费者 | 高 | 目标档位不提供空 accessor；残留引用必须导致构建失败，并执行全仓静态扫描 |
| AOT-free 被错误等同于 PGO-free | 高 | 阶段二使用独立 `PGO_PROFILER_ENABLED` 能力闭包；实测无 AOT、有 PGO 的 24 B 构建 |
| snapshot/AOT/AI/rawheap 版本不匹配 | 中 | feature fingerprint + 双向稳定拒绝；禁止只更新 runtime 而保留旧产物 |
| 汇编解释器或 GC visitor 越过目标对象边界 | 高 | offset/size 编译期断言、哨兵对象压力 GC、young/old/full/CMC 矩阵 |
| DFX 仍按 32 B 输出字段 | 中 | dump/hprof/rawheap/debugger 按当前构建能力输出，维护分档测试 |

## 5. 验收门槛

- 阶段一：JIT-free 构建无 cell `MachineCode` accessor、offset 和调用点，`ProfileTypeInfoCell::SIZE=24`，allocator 实际占用同步下降；
- 阶段二：JIT-free + PGO-free 构建另无 `Handle` accessor、offset 和调用点，`ProfileTypeInfoCell::SIZE=16`，allocator 实际占用同步下降；
- `Value`、Empty 哨兵、cell 创建/共享和 `CELL_0/1/N` 转级行为不变；
- 24 B 档的 PGO `Handle` 读写、dump/merge 和无 AOT + 有 PGO 场景回归通过；
- Interpreter、IC、AOT、GC、snapshot、serializer、AppSpawn、worker 回归通过；
- JIT-enabled 32 B 构建的 Fast/Baseline JIT、OSR、安装、deopt 和诊断回归通过；
- 各档位产物混用双向稳定拒绝；
- 快手及 Top13 clean A/B 的 cell 浅层堆下降符合 `8N/16N`，Region used/committed、峰值 RSS/PSS 和性能独立报告。

## 6. 依赖

- 阶段一依赖编译期 JIT 能力闭包，必须覆盖 Fast JIT、Baseline JIT、OSR、JIT deopt 和相关诊断；
- 阶段二依赖独立的编译期 PGO 能力闭包；关闭 AOT、未加载 AOT 文件或运行时未触发 AOT 均不足以删除 `Handle`；
- JSFunction 布局冻结为硬约束，本方案只修改 `ProfileTypeInfoCell` 自身；
- 两阶段均不改变 cell 数量，收益按全部现存 cell 计算。
