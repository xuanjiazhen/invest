# ProfileTypeInfoCell 惰性分配与 JIT-free 裁剪 —— 需求

本文件描述方案收益、工作量与风险。

## 1. 方案目标（两阶段）

**阶段一：惰性分配（全档位通用，V8 lazy feedback vectors 迁移）**——删除 DEFINEFUNC 即时分配（`interpreter-inl.cpp:1046` 等 7 处），被定义函数保持 `RawProfileTypeInfo = Empty`，cell 推迟到首次反馈写入（`SetProfileTypeInfo` 的 Empty 分支已具备该转换）或 PGO 触碰时分配。消除「从未收集反馈的函数」的 cell 驻留。

**阶段二：JIT-free 裁槽（编译期档位裁剪）**——面向编译期确定不包含 JIT 能力的产品变体（JIT-free，≤6G 内存分档即目标载体），删除 `MachineCode` tagged 槽，cell 从 32 B 缩减为 24 B；若该分档同时关闭 PGO 采集（PGO 数据仅服务 AOT 编译，AOT 关闭后无消费者，**需产品侧确认**），进一步删除 `Handle` 槽，缩减为 16 B。保留 `Value`（解释器/IC/PGO/AOT 读取）与 Empty 哨兵。

实施顺序：**先阶段一后阶段二**——惰性缩小裁槽的对象基数，避免为将死对象优化布局。

## 2. 收益（两阶段组合模型）

设 N=cell 存量（Top13 = 935,138），e=惰性消除率（1 − 首次反馈触发数/DEFINEFUNC 数，插桩实测；JIT-enabled 档位预期更低）：

| 阶段/组合 | 公式 | Top13 数值 |
|---|---|---|
| 阶段一（惰性，全档位） | e × N × 32 B | e×28.5 MiB（e=0.5 → 14.2；e=0.8 → 22.8） |
| 阶段二（24 B 档） | (1−e) × N × 8 B | (1−e)×7.13 MiB |
| 阶段二（16 B 档） | (1−e) × N × 16 B | (1−e)×14.27 MiB |
| **组合上限（惰性 + 16 B 档）** | N × (32e + 16(1−e)) B | e=0.5 → 21.4 MiB；e=0.8 → 25.6 MiB（绝对上界 28.5） |

cell_1/cell_n 同口径；收益边界不含 `ProfileTypeInfo`、`JSFunction` 各槽、Region 空洞与 committed/resident；最终以 clean A/B 实测放行。

**硬性前提**：目标尺寸必须对应实际对象尺寸和有效分配粒度；ArkVM young/old 空间按 8 B 对齐 bump 分配、无 32 B size class 取整（`DEFINE_ALIGN_SIZE` 对齐粒度 8 B），16/24 B 尺寸预期可全额兑现，但放行前仍须以 Region 实际占用核验，若被对齐 padding 抵消则不进入产品化。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| cell 尺寸被分配器取整抵消 | 中 | ArkVM tagged 对象按 8 B 对齐 bump 分配，无独立 size class 取整；放行前仍验证 Region 实际占用同步下降，否则不产品化 |
| 24/16/32 B 多档布局混用 | 高 | 同一镜像只允许一种尺寸；编译期能力闭包决定，运行时 `--jit=false` 不能切换；档位纳入构建 feature fingerprint |
| 残留 `MACHINE_CODE_OFFSET`/`HANDLE_OFFSET` 消费者 | 中 | 编译期移除接口（无空实现掩盖），残留消费者构建失败作静态校验 |
| snapshot/AOT/rawheap 版本不匹配 | 中 | feature fingerprint + 双向稳定拒绝 |
| 汇编解释器/GC visitor 越界 | 中 | 目标尺寸对象边界 + 哨兵对象压力 GC 验证 |
| 16 B 档误删仍需 PGO 的 Handle | 高 | 产品分档须先冻结「AOT 关闭 ⇒ PGO 关闭」决策；未冻结前 16 B 档不进入构建矩阵 |
| 惰性后 JIT 编译时序变化（无 cell 函数不可编译/降质） | 中 | 与 V8 行为对齐：预热前不编译本就是常态；AOT 质量回归对齐基线 |
| 惰性后 PGO define-class 采集缺失（Handle 无宿主） | 中 | PGO 开启构建保留 DEFINEFUNC 即时分配（条件分支） |
| 惰性首反馈路径多一次 Empty 判断 | 低 | 微基准 + 冷启动实测 |

## 5. 验收门槛（摘要）

- 阶段一（惰性）：快照 cell 节点数下降量 ≈ 插桩消除率 (n−m−p)/n；DEFINEFUNC 相关 7 处分配点删除；IC/PGO/AOT/JIT 全能力回归通过（预热后反馈行为不变）；冷启动与解释吞吐不回退超阈值；
- 阶段二（裁槽）：JIT-free 构建无 cell MachineCode accessor/offset/调用点；16 B 档另需无 Handle accessor/offset/调用点；`SIZE` 与档位一致且 allocator 实际占用同步下降；
- `Value`/Handle（24 B 档）/Empty 哨兵/cell 状态转换语义不变；Interpreter/IC/PGO（24 B 档）/AOT/GC/snapshot/AppSpawn 回归通过；
- JIT-enabled 32 B 构建及其 Fast/Baseline JIT、OSR、deopt 回归通过；
- 各档位产物混用双向稳定拒绝；
- Top13 clean A/B：cell 浅层堆下降符合两阶段组合模型；PSS 中位数之和稳定下降。

## 6. 依赖与插桩

- 阶段一无外部依赖，可独立先行；阶段二依赖编译期能力闭包（产品分档配置，≤6G 档关闭 AOT/JIT 为既定需求）；
- 16 B 档依赖产品确认「AOT 关闭 ⇒ PGO 采集关闭」；24 B 档无此依赖；
- JSFunction 布局冻结为硬约束（人工否决其代码槽移除），本方案只动 ProfileTypeInfoCell 自身，不受影响；
- **前置插桩**（消除率 e）：DEFINEFUNC 分配点计数（`interpreter-inl.cpp:1046` 入口）、首次反馈写入计数（`js_function.cpp:1199` Empty 分支）、PGO 触碰计数，输出 `elimination=(n-m-p)/n`——阶段一立项门槛。
