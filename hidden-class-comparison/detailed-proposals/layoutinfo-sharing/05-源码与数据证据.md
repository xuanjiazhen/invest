### 2.1 公式

```text
capacity = (self_size - 16) / 16
legacy fingerprint = (capacity, visible NumberOfElements, all physical key target identities)
v2 fingerprint = (capacity, NumberOfElements, all physical key target identities,
                  all physical Attr primitive target identities)
canonicalBytes = Σ one self_size per fingerprint group
gross = admittedBytes - canonicalBytes
tableCost = ceil(uniqueContents / 0.75) × 16
conditionalNet = gross - tableCost
```

`16` 字节 header 来自 snapshot 对该 revision TaggedArray `DATA_OFFSET` 的实测/源码一致性；脚本同时校验 `self_size >= 16` 且 `(self_size-16)%16==0`。任何不满足者排除为 `invalid_size`，不补值。

## 5. 口径限制

1. TOP13 v2 可证明同一快照内完整槽等价，但不能证明同内容对象属于同一 VM，也不能证明对象在创建后不再写；运行时命中必须由 per-VM 表域限制，后续写入必须 COW。
2. 严格模型排除 399 个对象 / 0.33 MiB，不补值；完整排除原因为 `invalid_size` 和 `unsupported_key_type`。
3. snapshot 的 HClass -> Layout owner 边可统计当前多 owner，不是历史 owner/transition 事件。
4. snapshot 缺边不解释为 Hole、未访问或可释放。
5. self_size 不含 key backing；最终方案不减少字符串/Symbol 内容，不计关联 backing 收益。
6. Region used/committed、RSS/PSS 不由 shallow 推算。
7. 相邻或前后台快照不相加、不相减、不视为同一原子时刻。
8. ConstantPool 与 Native Interop 的对象和收益未出现在脚本/JSON聚合中。
