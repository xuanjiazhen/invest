# LayoutInfo immutable canonical sharing —— 需求

本文件澄清要做的内容、收益、工作量与验收门槛，供项目管理者与评审决策。背景与前置知识见 [01-背景.md](01-背景.md)。

## 1. 要做的内容

在同一 ArkVM 内，把**完整物理内容相同的多个 LocalHeap LayoutInfo 对象收敛为一个 immutable canonical 实例**，共四件事：

| # | 内容 | 说明 |
|---|---|---|
| 1 | Layout 类型状态 | 新增 `MUTABLE_LAYOUT_INFO` / `IMMUTABLE_LAYOUT_INFO` 两个 HClass/type-state；物理槽格式与大小不变，immutable 只读 |
| 2 | Publish（内容寻址收敛） | Layout 构建结束、不再参与 transition 追加时，计算全物理内容 fingerprint（capacity、NumberOfElements、全部 key 槽、全部 Attr word），在 per-VM weak canonical table 中查找：命中则 owner HClass 改指向既有 canonical；未命中则本 Layout 转 immutable 并登记 |
| 3 | 写时复制（COW） | 全部 Layout 写入口（01-背景 §4 清单）统一经 `EnsureMutableLayout`：immutable 则整组复制为 mutable 后再写；TrackType 子树传播时相关 owner 共同脱离 |
| 4 | Per-VM weak canonical table + 双开关 | 每 VM 一张 weak-value 表（不保活 Layout/key）；build flag + runtime feature flag，默认关闭 |

**保持不变**（硬约束）：`HClass → Layout → [key, attr]` 读取路径、`JSHClass::LAYOUT_OFFSET` 与 compiler 固定偏移 ABI、TaggedArray 物理布局、transition-family 多 owner 复用、key identity/枚举序/representation/serializer/AOT/PGO 语义。

## 2. 收益

| 口径 | 值 | 性质 |
|---|---|---|
| 快手前台（严格内容模型） | 毛重复 8.17 MiB；扣 16B/entry 表成本后条件净 **7.74 MiB**（Layout shallow 12.96 MiB 的 60%） | 设计容量（两口径均未扣 COW/表头/锁，列为风险扣减） |
| 快手后台 full-GC 后 | 毛 6.76 MiB；条件净 **6.34 MiB** | 同上（与前台为独立终态，不相加） |
| Top13 合计 | shallow 109.25 MiB；缺 Attr 上界 gross 70.03 / 条件净 **66.03 MiB** | **上界**（旧快照无 Attr，不能当收益） |

Entry 尺寸敏感性：16/24/32 B 下快手前台条件净 7.74/7.52/7.31 MiB。PSS/Region 不由 shallow 换算，须 clean A/B 实测。

## 4. 风险（摘要，完整矩阵见 03-方案设计 §8）

| 风险 | 等级 | 一句话控制 |
|---|---|---|
| 漏收口写入口 → 多 HClass 状态串扰 | 高 | 全仓写调用点清单冻结（05 §1.2）+ immutable 直写断言 |
| transition family 过早 publish → 追加触发 COW 洪水 | 高 | 仍在增长的 family 不 publish；publish 后 COW 计数监控 |
| weak table 生命周期（保活/悬挂） | 高 | 复用既有 GC weak 容器机制，禁裸指针 |
| COW/表成本吞掉收益 | 中 | 快手 GC 后 LayoutInfo 净 shallow ≥4.0 MiB 且达基线 30% 为放行线 |
| 启动/publish CPU 回退 | 中 | publish 只在构建边界；启动中位 ≤1%、P95 ≤2% |

## 5. 验收门槛（摘要）

1. **正确性**：属性语义（增删改查/defineProperty/freeze/proto 变更）、TrackType 演化、AOT/PGO/serializer/snapshot 结果与基线一致；两 VM 同内容不互命中；无 local↔shared 新边；
2. **内存**：快手 GC 后 LayoutInfo 净 shallow ≥4.0 MiB（≥基线 30%）；Top13 新快照多 HClass 指向同一 canonical 的边如实呈现；
3. **性能**：启动中位 ≤1%/P95 ≤2%；查找/枚举热路径零改动验证（无 hash/锁/间接层）；transition 与 GC pause ≤2%；
4. **回退**：flag 关闭行为与现状完全一致；hash 冲突/异常一律不收敛，回退独立 LayoutInfo。

## 6. 依赖与非目标

- 无外部依赖；与 `layoutinfo-attr-packing` 正交（一个改份数、一个改每属性编码），若都实施，本方案先行（收敛后编码压缩的基数缩小）；
- 非目标：跨 VM/Realm/进程共享、SharedHeap 迁移、prefix-chain/parent+delta 结构、PropertyAttributes 打包、ConstantPool/Native Interop（收益不混算）。
