## 2. 验证方法

- 原始输入：`D:\docker\plan\top13` 下 13 份 `.rawheap`；应用版本、采集业务场景、精确采集时刻、进程/VM 数未冻结，均不可得。
- 转换器：DevEco Studio SDK `rawheap_translator.exe`，811,464 B，SHA-256 `c5c9df2b5683c56b5b93dba26ed3aef3f376c9d2f37110f1ba01086e44406990`。
- 输出 schema：13 份均为 `translated-v2`。fingerprint 包含 `capacity`、`NumberOfElements`、全部 physical key target identity、全部 physical Attr primitive target identity；identity 只在同一快照内比较。
- 尺寸：`capacity=(self_size-16)/16`；不满足尺寸约束的对象记为 `invalid_size`。不支持的 key node type 记为 `unsupported_key_type`。二者均排除，不把缺边补成 Hole。
- 收益：`gross=admittedBytes-canonicalBytes`；`tableCost=ceil(uniqueContents/0.75)*16`；`conditionalNet=gross-tableCost`。
- 确定性：13 份 rawheap 各转换两次，第二次输出 SHA-256 与第一次逐文件相同；census 运行两次，临时 JSON 27,935 B 字节级相同。仓库冻结 JSON 仅规范化为 LF，解析后的 JSON 内容与临时输出相同。

## 6. 证据与边界

- 逐应用 rawheap、translated-v2 临时输出的完整路径、字节数、SHA-256、translator object count、JSON nodes/edges 和结果字段见 `top13-layoutinfo-sharing-validation.json`；translated-v2 文件在哈希与 census 冻结后删除，rawheap 和 translator 保留用于复现。
- 严格 census 原始输出见 `top13-v2-layoutinfo-census.json`；逐应用可读明细见 `06-收益数据.csv`。
- snapshot 只证明采集终态的 shallow 对象内容，不证明创建次数、访问热度、未来 COW 频率或同内容对象处于同一 VM。方案因此仍限定为 per-VM LocalHeap，实际命中由运行时表域约束。
- shallow 不等于 Region used/committed、RSS 或 PSS。表头、tombstone、锁和 COW 副本没有从条件净中扣除，须由实现后的 clean A/B 验证。
- 13 个应用样本相互独立，不相加为同一物理时刻；快手后台 full-GC 样本不纳入 TOP13 合计。
