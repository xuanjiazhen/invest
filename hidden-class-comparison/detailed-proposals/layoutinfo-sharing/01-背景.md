# LayoutInfo immutable canonical sharing —— 背景

本文件如实呈现 LayoutInfo 的现状实现、全部问题与理解方案所需的前置知识，所有机制均配示例说明。源码事实冻结自 `ets_runtime@f04900cf951c66c2ea18b2bab5b591d5336c34b9`，逐条位置见 [05-源码与数据证据.md](05-源码与数据证据.md)。

## 1. LayoutInfo 是什么

`LayoutInfo` 是 `JSHClass` 的属性描述表：描述「这个 shape 有哪些属性、每个属性放在对象哪个槽位、可写/可枚举等元数据是什么」。每个 JS 对象经对象头的 HClass 指针找到 LayoutInfo，属性读写、枚举、序列化、AOT/PGO 类型推导都查这张表。

用一个对象走一遍全链：

```js
const p = { x: 1 };
p.y = 2;      // 发生 AddProperty transition：HClass 切到新 shape，新 shape 挂新的 LayoutInfo
p.x;          // 属性查找：obj → hclass → LayoutInfo 里查 "x" → 得到 x 的槽位/Attr → 到对象体内取值
```

```text
JSObject p ──对象头──► JSHClass(shape: {x,y})
                          │ Layout 强引用
                          ▼
                     LayoutInfo（TaggedArray 私有解释）
                     ┌────┬─────┬────┬─────┐
                     │ "x"│attr │ "y"│attr │   ← 每属性 2 个 tagged 槽：key + Attr
                     └────┴─────┴────┴─────┘
```

## 2. 物理格式（前置知识）

`LayoutInfo` 私有继承 `TaggedArray`（`layout_info.h:25-35`）：

| 字段 | 位置 | 语义 |
|---|---|---|
| 槽位 | `DATA_OFFSET` 起，每属性 2 槽 | 偶数槽 `2i` = key（String/Symbol 堆引用），奇数槽 `2i+1` = Attr（完整 `PropertyAttributes` tagged word） |
| `Length` | TaggedArray 头 | **= 2 × capacity**（容量按槽数计） |
| `ExtraLength` | TaggedArray 头 | **= NumberOfElements**（实际已添加的属性数） |

要点与示例：

- **capacity 与已用数分离**：创建 `CreateLayoutInfo(properties, type, mode)`（`object_factory.cpp:3483`）分配 `2×capacity` 槽并全部初始化为 `Hole`/默认 Attr（`layout_info.cpp:21-28`）；transition 追加属性时若容量富余则只把 `NumberOfElements +1`，不换数组。例如 capacity=8、已加 3 个属性：`Length=16`、`ExtraLength=3`，槽 6..15 留 `Hole`。
- **self_size = DATA_OFFSET + 16 × capacity**（`tagged_array.h:80-85`）；快照的 `self_size` 即数组浅层字节，不含 key 指向的 String/Symbol，也不含 owner HClass。
- **Attr 是完整 41 bit 载荷的 tagged word**：normal attr（writable/enumerable/configurable/representation/offset/trackType/sharedFieldType）+ sortedIndex + IsNotHole/IsConstProps/IsPGODumped 标志，编码为裸位透传（详见 `../layoutinfo-attr-packing/01-背景.md` §3.1）。**因此内容等价必须比较完整 Attr word，不能只比 key。**
- **读取热路径是固定偏移**：compiler/stub 直接 `Load(hclass + LAYOUT_OFFSET)`、`Load(layout + ATTR_INDEX_OFFSET)`，无哈希、无间接层（`js_hclass.cpp:1323-1441` 的 AOT/PGO/builtin lookup 均如此）。

## 3. 谁在读

| 读者 | 读什么 | 场景示例 |
|---|---|---|

## 4. 谁在写（全部原地写入点，共享方案必须处理的事实）

```js
// ① AddKey —— 加属性
p.y = 2;              // AddPropertyToNewHClass → AddKey 写 key/Attr/sortedIndex，ExtraLength+1

// ② SetNormalAttr —— 改属性元数据
Object.defineProperty(p, 'y', { writable: false });   // runtime CopyAndUpdateObjLayout 复制后改 Attr

// ③ UpdateTrackTypeAttr —— 类型反馈演化
;(() => { p.y = 1.5; })();   // TrackType 从 Int 粗化为 Double，原地改 Attr（可沿 transition 子树传播）

// ④ SetIsPGODumped —— PGO dump 去重标记
// PGO profiler dump layout 时置位（layout_info.cpp:191-228），Attr 更新时清位

// ⑤ SetIsNotHole / class extractor / runtime stub / shared-HClass 增量属性
// record 类字段初始化、class literal 构建、sendable 类加属性等路径
```

## 5. transition 现状：哪里共享、哪里复制

**已有的共享**（同一物理数组被多个 HClass 引用）：

- `Clone`/`CloneWithNewSizeAndType` 直接复用父 HClass 的 Layout（`js_hclass.cpp:227-269`）；
- `AddPropertyToNewHClass`（`js_hclass-inl.h:426-454`）在容量与 `NumberOfElements` 允许时**向共用数组追加**——transition 链的父子此刻共享同一数组，这正是 `ExtraLength ≥ 某个 owner 的 NumberOfProps` 的由来。

**复制点**（`CopyLayoutInfo`/`ExtendLayoutInfo`/`CopyAndReSort` 全量冻结清单见 05 §1.2）：

| 场景 | JS 示例 | 行为 |
|---|---|---|
| 加属性且容量不足 | 链上加到第 9 个属性（capacity=8） | `ExtendLayoutInfo` 扩容复制 |
| proto transition | `Object.setPrototypeOf(o, proto)` | `TransitionProto` 复制出**逐字节相同**的 Layout（`js_hclass.cpp:473`） |
| extensible transition | `Object.preventExtensions(o)` | `TransitionExtension` 同样复制相同内容（`:439`） |
| 属性元数据更新 | `Object.defineProperty(..., {writable:false})` | 复制整组后改一个 Attr 槽（`:773`、`runtime_stubs.cpp:605`） |
| IC 原型优化 | 原型链 IC 优化路径 | `OptimizePrototypeForIC` 复制（`:671`） |

proto/extensible 复制相同内容的原因是防御性隔离：LayoutInfo 会被 §4 的写入点原地修改，父子若共享数组，一方的 TrackType/PGO 标志会串到另一方。

## 6. 重复现状（实测数据）

**快手配对样本**（新版 translator，Attr 以 synthetic primitive node 输出，可做全物理槽严格比较）：

| 样本 | 场景 | HClass | distinct Layout | Layout shallow | 严格内容等价模型覆盖 |
|---|---|---:|---:|---:|---:|
| 前台 | 前台单点 | 76,848 | 69,745 | 12.96 MiB | 99.86% |
| 后台 | 进后台并确认 full GC 后单点 | 68,706 | 62,492 | 11.43 MiB | 99.84% |

内容重复（完整物理槽相等的不同对象）折算：TOP13 毛重复 69.64 MiB；快手前台 8.17 MiB、后台 6.76 MiB。已有多 owner（TOP13 中 12,261 个物理数组已被 96,011 条 HClass 引用；快手前台为 1,201 个 / 8,304 条）是 §5 已有共享，不计入新增收益。

**TOP13 全应用严格重放**：13 份原始 rawheap 由同一 v2 translator 重新转换，按 `(capacity, NumberOfElements, 全部 physical key identity, 全部 Attr tagged-word identity)` 比较。合计 Layout shallow 109.25 MiB，严格模型覆盖 99.946% 对象 / 99.697% 字节，gross 69.64 MiB，扣 16 B/entry 表成本后条件净 65.61 MiB。逐应用明细与口径见 [07-TOP13现状与收益验证.md](07-TOP13现状与收益验证.md)、[06-收益数据.csv](06-收益数据.csv)。旧 translator 的缺 Attr 结果 70.03 MiB 仅保留为历史上界对照。

两份口径都不能换算 PSS；快照是终态采样，不记录创建/写入/热度历史。

## 7. GC 与并发语义（前置知识）

- LayoutInfo 按 `TAGGED_ARRAY` 扫描全部 `Length` 槽（`tagged_array.h:126-132`）；key 是强引用，数组存活即保活 key；
- `JSHClass::Layout` 是 synchronized tagged accessor（含读屏障），visitor 覆盖该槽（`js_hclass.h:2214-2225,2277`）；
- Local HClass 的 Layout 在 LocalHeap；Shared HClass 可持有 SharedHeap Layout；**LocalHeap 对象不得引用 SharedHeap key，反向引用同理**——任何跨域共享都要显式处理；
- 既有 weak 容器先例：TransitionsDictionary 的弱 value（`transitions_dictionary.h`），GC 提供 weak 清理/移动更新机制。
