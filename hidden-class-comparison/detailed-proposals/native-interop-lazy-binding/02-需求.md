# Native Interop 闭包惰性原型绑定 —— 需求

本文件描述方案收益、工作量与风险。

## 1. 方案目标

把 `napi_define_class` 在类定义时即时创建 prototype 方法闭包的行为，改为**首次属性访问时按需创建**，消除完整 Bucket C 中可归因于 prototype 方法 slot 的方法闭包分量。完整 Bucket C 同时包含零实例类对应的 constructor 闭包；constructor 不属于当前 A2 直接收益，必须分列。

## 2. 收益

| 指标 | 值 | 性质 |
|---|---|---|
| Bucket C 方法闭包分量（A2 直接目标） | 61.474 MiB | **上界**（447,707 个） |
| Bucket C constructor 分量（非 A2 直接目标） | 7.062 MiB | **上界**（57,737 个） |
| 完整 Bucket C 闭包本体 | 68.536 MiB | **上界**（505,444 个） |
| 方法分量同步消除的 JSNativePointer | 17.079 MiB | A2 上界，与方法分量同比例折减 |
| 方法分量堆外 NapiFunctionInfo | 13.663–17.079 MiB | A2 上界，与方法分量同比例折减 |
| 期望值 | 未知 | 需插桩「从未被读取的方法占比」后折算 |

**A2 收益不能按 61.474 MiB 方法分量全量列入**（零实例是「未访问」的代理指标，存在双向偏差，见背景 §4）。完整 Bucket C 的 68.536 MiB 仅用于存量守恒，不能作为 A2 收益承诺。

## 3. 工作量与排期（估计）

| 任务 | 说明 | 人日 |
|---|---|---|
| 插桩统计（前置） | Phase 1 复用 NAPI profiler 统计 callback 调用率，并给出未读取率上界；Phase 2 经属性读取全路径覆盖后统计未读取占比 | 5–8（Phase 1；Phase 2 另评估） |
| A1 类粒度 | 模块导出对象装 `InternalAccessor`，类名首次读取才 define_class | 10–15 |
| A2 方法粒度 | per-slot 惰性标记 + property lookup 全路径 + IC 失效 | 20–30 |
| 兼容性处理 | descriptor/赋值/freeze/sendable/module unload | 10–15 |
| 验证与回归 | property semantics/GC/worker/并发 | 10–15 |

总量级：A1 约 3–5 人周，A2 约 6–9 人周（**需先插桩定收益与选型后细化**）。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| 收益期望值未知（61 MiB 是上界） | 高 | 先插桩定「未访问方法占比」再排期 |
| A1 vs A2 选型 | 中 | A1 整类 materialize 敏感；A2 收益上限高但改全路径 |
| materialize 后 IC 未失效（错误 handler 命中） | 高 | 复用既有原型链失效机制（MarkProtoChanged + listener 刷新 + MegaIC 清理），方案设计 §4.4 固化 |
| `ResetLazyInternalAttr` 原地改共享 LayoutInfo 影响 IC | 高 | per-slot 原子 materialize + IC invalidation |
| descriptor 深拷贝堆外驻留抵扣收益 | 中 | 插桩同步量化 descriptor 驻留字节；超过消除量 20% 时静态存储期契约转主路径（方案设计 §4.5） |
| descriptor 数组生命周期 | 中 | 深拷贝或静态存储期契约 |
| sendable 类 | 中 | 排除（跨线程共享，需即时路径） |
| 与编译期裁剪收益重叠 | 中 | 同一存量两条路径，收益不可叠加 |

## 5. 验收门槛（摘要）

1. Phase 1 先得到 callback 调用率下界和未读取率上界；仅当解释器/IC/compiler/AOT/反射读取全路径覆盖验收通过后，Phase 2 才输出「从未被读取的方法占比」并折算期望收益（≤61 MiB）；
2. property semantics 全兼容：`getOwnPropertyDescriptor` 形态、严格模式赋值、`Object.freeze/seal`、`delete`、proxy、debugger；
3. sendable 类保持即时路径；worker/sendable/异常重入/module unload/GC 回归通过；
4. IC 失效正确（materialize 后原型链 IC 不命中错误 handler）；
5. 两版快照对比确认 Bucket C 减少。

## 6. 依赖

- 依赖 NAPI 侧配合（descriptor 生命周期契约）与 VM property lookup（A2）；
- 与方案 02（应用侧 getter 惰性导入）针对同一存量，**收益不可叠加**。
