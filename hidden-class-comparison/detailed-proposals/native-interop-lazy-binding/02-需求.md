# Native Interop 闭包惰性原型绑定 —— 需求

本文件描述方案收益、工作量与风险。

## 1. 方案目标

把 `napi_define_class` 在类定义时即时创建 prototype 方法闭包的行为，改为**首次属性访问时按需创建**，消除完整 Bucket C 中可归因于 prototype 方法 slot 的方法闭包分量。完整 Bucket C 同时包含零实例类对应的 constructor 闭包；constructor 不属于当前 A2 直接收益，必须分列。

正式实现采用 **A2 + X1 + 最小 VM-owned recipe**：

- 不保存调用方 `napi_property_descriptor[]` 数组；
- 不保存调用方临时 `utf8name` 指针或跨 handle scope 的裸 `napi_value`；
- 每个 eligible prototype method 只复制 `method` 和 `data` 两个指针值，形成 16 B、8 B 对齐的 `NativeLazyMethodRecipe`；
- 属性键/名称和 attributes 使用已安装 prototype 槽中的 VM-owned key 与 `PropertyAttributes`，由专用 lookup 传入物化路径；
- `data` 是非拥有指针值，recipe 不释放其目标资源，module/env 必须保证其在 lazy lifetime 内有效；
- X1 accessor 按 32 B/未物化槽计；每个未物化槽独立拥有一个 16 B recipe allocator block；每类 `atomic<uintptr_t> slotDirectory[N]` 按 8 B/eligible slot 计。ClassBindingLifetime、registry/header、recipe allocator actual 和 GC/物理内存成本独立计费。

A1 在类/prototype 尚未创建时不能从 LayoutInfo 恢复 key/attributes，不使用 A2 的 16 B recipe 数字；A1 只有在完整类 recipe 另行设计并评审后才可实施。

## 2. 收益

| 指标 | 值 | 性质 |
|---|---:|---|
| Bucket C 方法闭包分量（A2 直接目标） | 61.474 MiB | **上界**（447,707 个，方法闭包数） |
| Bucket C constructor 分量（非 A2 直接目标） | 7.062 MiB | **上界**（57,737 个） |
| 完整 Bucket C 闭包本体 | 68.536 MiB | **上界**（505,444 个） |
| 方法分量同步消除的 JSNativePointer | 17.079 MiB | A2 上界，与方法分量同比例折减 |
| 方法分量堆外 NapiFunctionInfo | 13.663–17.079 MiB | A2 上界，与方法分量同比例折减 |
| A2 X1 惰性 accessor | 32 B/未物化方法槽 | 设计成本，待最终类型 ABI probe；首次物化写回后可回收 |
| A2 最小 owned recipe | 16 B payload/未物化槽 | 每槽独立 allocator block；按 allocator actual 计费，物化/覆盖/删除后立即释放 |
| tagged slot directory | 8 B/全部 eligible 槽 | 每类连续 `atomic<uintptr_t>[N]`；全部终态、批量终止或 unload 后整体释放 |
| 期望值 | 未知 | 需 Phase 2 读取全路径覆盖后按未物化槽比例折算 |

A2 净收益不能按 61.474 MiB 方法分量全量列入。通用公式为：

```text
Net = Σ(未物化槽的 eager avoided bytes
        − 32 B accessor
        − recipe allocator actual bytes)
      − align8(8 B × 全部 eligible 槽数)
      − ClassBindingLifetime/registry/header/GC 实际成本
```

零实例和 full-GC 仅构成结构候选上界，不能证明方法从未读取/调用；完整 Bucket C 只用于存量守恒，不能作为 A2 收益承诺。recipe 按槽物化后立即释放；若少数未物化槽的剩余 avoided bytes 不再覆盖 live recipe actual、8N B directory 与类固定成本，必须批量物化剩余槽并释放 directory/token。

## 3. 工作量与排期（估计）

| 任务 | 说明 | 人日 |
|---|---|---:|
| 插桩统计（前置） | Phase 1 复用 NAPI profiler 统计 callback 调用率，并给出未读取率上界；Phase 2 经属性读取全路径覆盖后统计未读取占比 | 5–8（Phase 1；Phase 2 另评估） |
| A1 类粒度 | 模块导出对象装 `InternalAccessor`，类名首次读取才 define_class；需要另行设计完整类 recipe 和注册契约 | 10–15 |
| A2 方法粒度 | per-slot 惰性标记 + 专用 key 传递 + property lookup 全路径 + IC 失效 | 20–30 |
| 最小 recipe/生命周期 | 独立 method/data recipe allocation、tagged directory、局部收益门控、批量终止、env cleanup/DEAD | 5–8 |
| 兼容性处理 | recipe/属性键传递/赋值/freeze/sendable/module unload | 10–15 |
| 验证与回归 | property semantics/GC/worker/并发/allocator 与 clean A/B | 10–15 |

总量级：A2 正式实现约 7–11 人周（插桩与 Phase 2 全路径另评估）；A1 不纳入本次正式实现排期。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| 收益期望值未知（61 MiB 是上界） | 高 | 先完成 Phase 2，按类输出 `N/U` 与读取形态，再折算期望值 |
| recipe/accessor/directory/固定成本抵扣收益 | 高 | 每类单独计算 `N/U`；扣除 32 B accessor、recipe allocator actual、8 B/eligible slot directory 和实际固定成本，局部净收益不正则走即时路径 |
| 调用方 descriptor 数组和临时名称已失效 | 高 | define_class 返回前只复制 `method/data`；禁止保存 descriptor、`utf8name`、裸 `napi_value` |
| lookup 不传属性键导致必须复制名称 | 高 | X1 增加专用 `CallNapiLazyGet(thread, holder, key)` 或等价 key-aware 分发；未闭合前不得上线 |
| 少数未访问槽长期钉住 directory 与 live recipe blocks | 高 | recipe 按槽物化后立即释放；剩余收益不覆盖实际驻留时批量物化并释放 directory/token |
| A1 vs A2 选型 | 中 | 本次正式实现固定 A2；A1 需完整类 recipe/契约另行评审 |
| materialize 后 IC 未失效 | 高 | 复用既有原型链失效机制（MarkProtoChanged + listener 刷新 + MegaIC 清理） |
| sendable 类 | 中 | 排除（跨线程共享，保留即时路径） |
| 与编译期裁剪收益重叠 | 中 | 同一存量两条路径，收益不可叠加 |

## 5. 验收门槛（摘要）

1. Phase 1 先得到 callback 调用率下界和未读取率上界；仅当解释器/IC/compiler/AOT/反射读取全路径覆盖验收通过后，Phase 2 才输出“从未被读取的方法占比”；
2. recipe ABI 只含 `method + data` 两个指针，实测为 16 B/slot、8 B 对齐；不复制名称、attributes、getter/setter/value 或调用方 descriptor 数组；
3. 专用 lazy lookup 能把当前 VM String/Symbol key 传给物化路径，`fn.name/length`、`proto.m === proto.m` 与即时绑定一致；
4. property semantics 全兼容：`getOwnPropertyDescriptor` 形态、严格模式赋值、`Object.freeze/seal`、`delete`、proxy、debugger；
5. sendable 类保持即时路径；worker/sendable/异常重入/module unload/GC 回归通过；
6. IC 失效正确（materialize 后原型链 IC 不命中错误 handler）；
7. module unload 先置 `DEAD` 并等待现有 guard 排空，再释放剩余 recipe/directory/token，不释放 `data` 目标资源；
8. 两版快照/clean A/B 确认 Bucket C 减少，并将 accessor、recipe allocator actual、directory、lifetime/registry/header、GC/Region/RSS/PSS 成本分开报告。

## 6. 依赖

- 依赖 NAPI 侧建立最小 owned recipe，VM property lookup 为专用惰性 getter 传入当前属性键（A2）；
- A1 的完整类 recipe和模块注册契约不属于本次正式实现；
- 与方案 02（应用侧 getter 惰性导入）针对同一存量，**收益不可叠加**。
