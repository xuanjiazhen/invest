## 2. 尺寸模型

```text
physical TaggedArray slots = 2 × capacity
self_size = 16 + 16 × capacity
one capacity slot = 16 B
```

普通 GROW 输入为 `N` 且未触及上限时：

```text
old_capacity = N + 4
compact_capacity = N
saving = 4 × 16 = 64 B / LayoutInfo
```

## 3. 快照结构上界

新脚本 `layoutinfo_compact_capacity_census.py` 从 snapshot `self_size` 反推 physical capacity，并按连续 live key/Attr prefix 得到 effective property count。该值只表示结构上界。

| 样本 | admitted LayoutInfo | current shallow | compact-capacity slack upper bound |
|---|---:|---:|---:|
| 快手前台 | 69,735 | 13,574,224 B | 3,348,784 B（3.19 MiB） |
| 快手后台 full-GC 后 | 62,482 | 11,963,344 B | 3,106,544 B（2.96 MiB） |
| TOP13 独立快照合计 | 735,734 | 114,555,552 B | 20,662,928 B（19.71 MiB） |

快手前台 0～4 属性子集上界为 1,812,256 B（1.73 MiB）。TOP13 和快手快照均缺少完整创建来源、后续写入历史和可靠 N-API 归因，因此不能作为发布收益或 RSS/PSS 预测。
