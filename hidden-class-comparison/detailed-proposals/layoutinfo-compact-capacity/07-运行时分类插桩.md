# LayoutInfo 确定性容量策略：运行时分类插桩

## 目标

在不改变默认行为的前提下，记录 LayoutInfo 的创建来源、初始 capacity、最终属性数、后续追加/扩容和复制成本，为外部画像和容量策略选择提供可复算输入。

## 记录字段

```text
creation_site
layout_kind
runtime/source revision
ABI/configuration
bundle/module/class identity
profile schema version
properties_argument
initial_capacity
final_property_count
hclass_inline_capacity
is_dictionary
is_aot
is_shared
append_after_create
extend_count
copy_bytes
create_latency
```

不输出原始路径、地址或用户数据；class identity 使用内部稳定 ID。

## 布局类别

```text
fixed_builtin
final_by_construction
napi_class
ordinary_transition
pgo_root
pgo_child
aot_restore
shared_or_sendable
dictionary
other
```

## 运行时状态

```text
UNKNOWN -> WARMING -> STABLE -> INVALIDATED
```

- `UNKNOWN`：没有有效画像，使用 GROW；
- `WARMING`：收集样本，使用 GROW；
- `STABLE`：画像和当前 identity/schema 匹配，允许预测容量；
- `INVALIDATED`：版本、schema、原型/继承关系或实际行为变化，清除画像并回到 GROW。

## 候选策略输出

对每个候选 capacity `C` 输出：

```text
initial_slack_bytes
append_or_extend_count
copy_bytes
create_latency_p50/p95
```

测试候选：

```text
C = final_count
C = percentile(final_count, q) + reserve
C = existing GROW
```

`q` 和 `reserve` 必须在独立验证样本上选择，不能看完结果后回填。

## 放行条件

- profile identity 完整匹配；
- 预测容量不足时有明确 copy/extend fallback；
- 没有越界写；
- fallback 率和 copy bytes 在预设门限内；
- 创建 P50/P95 不恶化；
- LayoutInfo shallow、Region used/committed 和 RSS/PSS 的 clean A/B 结果为正。

概率信息只用于容量预测，不单独构成安全证明。
