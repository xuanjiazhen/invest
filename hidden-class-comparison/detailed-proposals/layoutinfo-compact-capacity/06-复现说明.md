## 计算

脚本对每个 LayoutInfo：

1. 从 `self_size` 反推 physical capacity；
2. 读取连续 live key/Attr prefix 的 effective property count；
3. 计算当前大小 `16 + 16 × physical_capacity`；
4. 计算假设压到有效属性数后的大小 `16 + 16 × effective_property_count`；
5. 输出两者差额作为结构 slack upper bound。

## 解释边界

- 结果是 terminal heap snapshot 的结构上界，不是创建路径收益；
- snapshot 不记录后续追加历史、PGO family 生命周期或策略造成的 copy/extend；
- `capacity == effective_property_count` 只有在创建路径证明最终性后才能发布；
- Region used/committed、RSS/PSS 和 allocator rounding 必须通过 clean A/B；
- 复算脚本通过不等于 ArkCompiler C++ 全套测试通过。
