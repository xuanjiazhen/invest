# LayoutInfo 属性描述槽压缩 —— 背景

本文件存放理解本方案所需的背景知识与现有实现介绍。

## 1. LayoutInfo 是什么

`LayoutInfo`（`layout_info.h:30`，私有继承 `TaggedArray`）是 JSHClass 的属性布局数组：每个属性以「Key 槽 + Attr 槽」两个 8 B tagged 槽交织存放（`ELEMENTS_INDEX_LOG2` 交织编址，`layout_info-inl.h:40-90`）。Key 是属性名（堆引用），Attr 是 `PropertyAttributes`——本质 uint32 位域（writable/enumerable/configurable/fast-rep 等），经 `GetNormalTagged()` 以 tagged 值写入整 8 B 槽。

例如，对象依次增加 `id`、`name`、`active` 三个属性后，其 JSHClass 对应的 `LayoutInfo` 可按下面的逻辑视图理解：

```javascript
const user = {
	id: 1001,
	name: "Ada",
	active: true,
};
```

| 数据区槽位 | 物理偏移（含 16 B 头） | 内容示例 | 含义 |
|---:|---:|---|---|
| 0 | 16 B | Key(`id`) | 指向属性名字符串 `id` 的 tagged 堆引用 |
| 1 | 24 B | Attr(`id`) | `id` 的属性序号/偏移、writable、enumerable、configurable、representation 等位域 |
| 2 | 32 B | Key(`name`) | 指向属性名字符串 `name` 的 tagged 堆引用 |
| 3 | 40 B | Attr(`name`) | `name` 对应的同类属性描述位域 |
| 4 | 48 B | Key(`active`) | 指向属性名字符串 `active` 的 tagged 堆引用 |
| 5 | 56 B | Attr(`active`) | `active` 对应的同类属性描述位域 |

也就是第 `i` 个属性使用 `GetKeyIndex(i) = 2i` 和 `GetAttrIndex(i) = 2i + 1` 两个相邻槽位：

```text
对象头（16 B） | Key(id) 8 B | Attr(id) 8 B | Key(name) 8 B | Attr(name) 8 B | Key(active) 8 B | Attr(active) 8 B
```

这里的 Attr 示例表示它承载的信息种类，不限定某个具体十六进制编码；实际值由属性定义方式和存储位置决定。关键在于：Attr 的有效载荷来自一个 32 bit `PropertyAttributes`，但 `GetNormalTagged()` 会把它包装成 64 bit tagged 值，因此仍占用完整 8 B 槽。上例共 3 个属性，当前对象尺寸为 `16 B + 3 × (8 B + 8 B) = 64 B`。

## 3. Attr 槽的编码结构与浪费

### 3.1 槽内实际载荷：最多 41 bit，不止「布局真值」28 bit

Attr 槽是裸位透传编码：写入 `WrapUint64(v) = v | TAG_INT`，读出 `UnwrapToUint64` 取回全部位（`js_tagged_value.h:832-840`；读取构造 `PropertyAttributes(JSTaggedValue)` 不截位，`property_attributes.h:93`）。位分区（`property_attributes.h:111-147`）：

| 位段 | 字段 | 归属 |
|---|---|---|
| 0–27（28 bit） | metaData(4) + isInlined(1) + Representation(2) + Offset(10) + TrackType(3) + SharedFieldType(8) | **布局真值**（`GetNormalAttr` 掩码范围，`NORMAL_ATTR_BITS=28`） |
| 28–37（10 bit） | SortedIndex（按 key hash 的查找排序索引） | 运行时缓存 |
| 38 / 39 / 40（3 bit） | IsConstProps / IsNotHole / IsPGODumped | 语义标志 / 语义标志 / PGO dump 瞬态标记 |

写入路径核验（哪些位真的会进 LayoutInfo 槽）：

| 写入者 | 位置 | 写入位宽 |
|---|---|---|
| `SetPropertyInit`（AddKey 初始化） | `layout_info-inl.h:61-64` | 仅 28 bit（`GetNormalTagged()` 掩码） |
| `SetSortedIndex`（AddKeyCommon 插入排序维护，**每次加属性都执行**，`layout_info-inl.h:351-353`） | `layout_info-inl.h:105-111` | 读出→设 bit28-37→`GetTaggedValue()` **整宽写回** |
| `SetNormalAttr` / `UpdateTrackTypeAttr` | `layout_info-inl.h:67-72,300-307` | 保留高位、更新低 28 位（并清 IsPGODumped），整宽写回 |
| `SetNotHole` / `SetIsPGODumped`（PGO dump 路径 `layout_info.cpp:195,217`） | `layout_info-inl.h:296-315` | bit39 / bit40 |
| record const 标记 | `runtime_stubs-inl.h:835` | bit38 |

即：**存活 LayoutInfo 的 Attr 槽常态携带 38–41 bit**（28 位布局真值 + 10 位排序索引 + 3 位标志）。

### 3.2 浪费结构

Attr 槽有效载荷 ≤41 bit（含 13 bit 非布局真值），却占满 8 B tagged 槽；若只算布局真值 28 bit，则利用率 34%。`TaggedArray` 体系已有原生字段先例（`JSNativePointer`、`InternalAccessor` 的 `ACCESSORS_FIXED_SIZE_FIELD`）。压缩可行档位由「迁不迁移 13 个运行时位」决定（见 02-需求两档收益）。

## 4. 消费者边界（源码核验）

- 定义与访问器：`layout_info.h` / `layout_info-inl.h`（`GetKeyIndex`/`GetAttrIndex`/`GetAttr`/`SetAttr`）；
- 查找链：`js_hclass` 的 `LookupProperty*` 家族（fast/prototype/builtin/AOT/PGO 五入口）与 transition 追加属性路径；
- 枚举：`LayoutInfo::GetAllKeys/GetAllEnumKeys` 系列；
- AOT 编译的固定偏移读取（`LookupPropertyInAotHClass`）——内部编译契约，需版本 bump；
- GC：Attr 槽当前为 Smi 值（visitor 天然跳过），改 raw u32 后按 Key 区长度扫描，语义等价；
- 工具：serializer 案例表、heap snapshot/rawheap metadata、`js_metadata_test`。
