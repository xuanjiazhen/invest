# LayoutInfo 属性描述槽压缩 —— 需求

本文件描述方案收益、工作量与风险，供项目管理者与评审决策。

## 1. 方案目标

把 `LayoutInfo` 每属性的 Attr 存放从 8 B tagged 槽改为 4 B 原始 uint32 区（分离双区布局：Key 区 8 B tagged + Attr 区 4 B raw），每属性 16 B → 12 B，对象尺寸公式改为 `align8(DATA_OFFSET + 8N + 4N)`。

## 2. 收益

| 指标 | 值 |
|---|---|
| 精算收益（Top13 全量逐数组，含对齐） | **23.17 MiB / 21.2%**（109.25 → 86.08 MiB） |
| 对齐损失 | 相对朴素模型（24.5 MiB）仅 1.35 MiB：8 B 对齐只在 N 为奇数时引入 4 B padding；N≤1 的 75,170 个（10.2%）节省为 0 |
| 与 JSHClass AuxData Sidecar 叠加 | 同对象族不同数组，收益可叠加（17.7 + 23.2 = 40.9 MiB）；同批版本 bump 可共用一次 clean rebuild |
| 收益边界 | 浅层堆口径，不含 Region 空洞与 PSS；放行以 clean A/B 实测为准 |

## 3. 工作量与排期

| 任务 | 设计 | 开发 | 测试 | 小计 |
|---|---:|---:|---:|---:|
| 双区布局与访问器（layout_info.h/-inl.h） | 2 | 5 | 3 | 10 |
| 查找链迁移（LookupProperty 五入口、transition、枚举） | 2 | 5 | 5 | 12 |
| AOT 编译偏移与版本契约 | 2 | 3 | 3 | 8 |
| GC visitor / serializer / snapshot / rawheap / metadata test | 1 | 5 | 4 | 10 |
| Top13 clean A/B 与性能（LookupProperty 热路径） | 1 | 1 | 7 | 9 |
| **合计** | **8** | **19** | **22** | **49 人日** |

人员配置：1 runtime + 1 compiler + 1 测试，日历排期约 5 周；与 AuxData Sidecar 同批实施可摊薄版本/工具链工作（合计可省 6–8 人日）。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| LookupProperty 热路径性能回退（Attr 地址计算复杂化） | 中 | 双区布局保持各区内连续；解释器 + AOT 两条查找链基准，回退阈值 ≤1% |
| AOT 固定偏移读取失配 | 中 | 与 AuxData Sidecar 同批 bump `.an/.ai` 版本，clean rebuild，新旧产物双向拒绝 |
| 属性数与 Attr 区长度一致性 | 中 | 长度字段单一来源 + heap verification 断言 |
| Attr 区越界（raw 区不被 GC 感知） | 中 | 哨兵对象压力 GC 用例（Attr 区末尾后放哨兵，验证不被覆写/误扫） |

## 5. 验收门槛（摘要）

- `ComputeSize == align8(16 + 12N)`，Top13 新快照 Layout self_size 逐数组符合公式、总降幅 ≥20 MiB；
- 属性查找/transition/枚举/AOT/PGO/序列化全回归通过；LookupProperty 微基准与属性访问 IC 回退 ≤1%；
- GC 矩阵（young/old/full/CMC）+ heap verification + 哨兵越界用例通过；
- PSS 中位数不回退；与 AuxData Sidecar 合批时新旧产物双向稳定拒绝。

## 6. 依赖

- 无新编译宏依赖；与 ≤6G JIT/AOT-off 分档正交（布局压缩对档位无感知）；
- 版本契约与 `jshclass-auxdata-sidecar` 建议同批（一次 clean rebuild 覆盖两项）。
