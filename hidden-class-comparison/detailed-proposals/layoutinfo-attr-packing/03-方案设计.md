# LayoutInfo 属性描述槽压缩 —— 方案设计（按架构特性设计模板）

## 1、特性需求/问题/动机的来源与价值

**问题来源**：Top13 复算发现 LayoutInfo 数组合计 109.25 MiB（735,734 个去重对象），是 JSHClass 本体（68.78 MiB）的 1.59 倍。每属性以 Key 8 B + Attr 8 B 交织存放；Attr 槽是裸位透传（`WrapUint64`/`UnwrapToUint64`），实际载荷最多 **41 bit**——28 bit 布局真值 + 10 bit SortedIndex（按 hash 的查找排序索引）+ 3 bit 标志（IsConstProps/IsNotHole/IsPGODumped），却占满 8 B 槽。

**价值**：按「是否迁移 13 个运行时位」分两档——A 档 6 B raw 无损等价，精算 **10.42 MiB / 9.5%**；B 档 4 B raw（迁移后仅存 28 bit 布局真值），精算 **23.17 MiB / 21.2%**。与 JSHClass AuxData Sidecar 同对象族不同数组、收益可叠加、版本契约可同批。

**实现前 vs 实现后（用户视角）**：实现前每个 shape 的属性描述占 16 B/属性；实现后 14 B（A 档）或 12 B（B 档），属性查找、transition、枚举、序列化行为完全不变。

## 2、特性影响分析

### 2.1 系统位置

对象模型核心（JSHClass → LayoutInfo 属性查找链），影响属性访问、对象创建/transition、枚举、AOT 编译偏移、GC visitor、序列化与快照工具。

### 2.2 环境依赖

- 无档位/多 target 差异（64 位布局，对 JIT/AOT-off 分档无感知）；
- 单一布局，不允许新旧交织混堆。

### 2.3 涉及模块

`layout_info{.h,-inl.h,.cpp}`、`js_hclass` 查找链与 transition、GC visitor/write barrier（仅 Key 区）、serializer、heap snapshot/rawheap metadata、`js_metadata_test`、AOT 编译偏移与 `.an/.ai` 版本。

### 2.4 前后版本兼容性

- 不改变公开 API、字节码格式、JSHClass/JSFunction 布局（**JSFunction 布局冻结约束不受影响**）；
- LayoutInfo 元素偏移是 ArkVM 内部编译契约（AOT `LookupPropertyInAotHClass` 固定偏移读取）：bump `.an/.ai` 版本 + strict match 拒绝旧产物、clean rebuild；rawheap metadata 同步，旧 translator 对新 rawheap 因版本不匹配失败。

### 2.5 外部用户感知

无（属性语义、枚举顺序、序列化结果不变）。

### 2.6 性能影响

- 时间：Attr 读取从「交织 +1 槽」改为「同下标另一区首址 + 4B 步进」，均为一次额外加法；查找链微基准与 IC 全状态回归设 ≤1% 阈值；
- 空间：−23.17 MiB（Top13 浅层精算）；GC 扫描槽减半（Attr 区不再作为 tagged 槽）。

## 3、业界竞品分析

| 引擎 | 对应结构 | 做法 |
|---|---|---|
| V8 | `DescriptorArray` | key/details 分列存放，details 为紧凑位域；数组跨 Map 共享 |
| JSC | `PropertyTable` | key/attributes 分列，attributes 紧凑编码 |
| ArkVM（现状→本方案） | `LayoutInfo` | 交织 Key/Attr 双 tagged 槽 → 分离双区（Key tagged + Attr raw u32） |

本方案即向竞品的「分列 + 紧凑位域」形态靠拢；跨 hclass Layout 共享（V8 DescriptorArray 共享）受 transition 前缀共享天然上限（0.898）约束，另行评估。

## 4、本特性的设计/实现方案

### 4.1 目标布局（分离双区，A/B 两档）

```text
现状（交织，每属性 16 B）             A 档（双区，14 B/属性）        B 档（双区，12 B/属性）
header 16 B                          header 16 B                    header 16 B
key0  attr0  key1  attr1  …          key0  key1 …（8 B tagged）      key0  key1 …（8 B tagged）
                                     attr 区：6 B/项（全 41 bit）     attr 区：4 B/项（28 bit 真值）
                                                                    + SortedIndex/标志迁移
```

尺寸公式：A 档 `align8(16 + 14N)`；B 档 `align8(16 + 12N)`。编址：`KeyIndex(i) = 16 + 8i`、`AttrIndex(i) = 16 + 8N + k·i`（k=6 或 4）；长度字段单一来源（N），heap verification 断言两区边界。

**A 档为无损退路**：所有既有写入者（含 `SetSortedIndex`/`SetIsPGODumped` 等 41 bit 路径）不改语义，仅换编码容器；对齐后收益 10.42 MiB。

**B 档为目标形态，需三项迁移设计冻结**：

1. **SortedIndex（10 bit，硬骨头）**：索引服务 `AddKeyCommon` 插入序维护与按 hash 的二分查找。迁移选项：(a) 独立 u16 索引区——每属性变 4+2=6 B，收益回落 A 档，仅换复杂度不取；(b) **Key 区改 hash 有序存放**（V8 DescriptorArray 同型：条目按 key hash 排序，二分直接查 Key 区，无独立索引）——枚举顺序改由 EnumCache/插入序侧表保证，查找与枚举链联动重审；(c) 查找时重算。推荐方向 (b)，须先做查找/枚举双链影响评估。
2. **IsConstProps/IsNotHole（2 个语义位）**：折进 SharedFieldTypeField（8 bit 编码空间未占满）或 Representation 空余编码；
3. **IsPGODumped（瞬态标记）**：改 PGO dump 会话内的堆外去重集合（hclass+index 键），dump 结束丢弃，堆内零占用。

**不采用交织编址**：Attr 地址按非 8 倍步进交错，编译侧与循环展开不友好；双区使 Attr 区连续，「Key 区查找 + Attr 区同下标读取」与现状访问模式差异最小。

**不进一步打包至 2 B**：28 bit 真值 >20 bit，且 uint32 语义被序列化/调试直接消费。

### 4.2 访问器与 GC

- `GetAttr/SetAttr` 走 `GetPrimitive` 类 raw 访问（`ACCESSORS_FIXED_SIZE_FIELD` 先例）；`GetKey/SetKey` 维持 tagged 访问与 write barrier；
- visitor 只扫 Key 区（现状 Attr 是 Smi、扫描时天然跳过，语义等价）；moving GC 只更新 Key 槽；
- Attr 为 raw，无屏障、无扫描——Attr 区末尾后放置哨兵对象的压力 GC 用例验证不被覆写/误扫。

### 4.3 查找链迁移

`LookupProperty*` 五入口（fast/prototype/builtin/AOT/PGO）与 transition 追加路径、`GetAllKeys/GetAllEnumKeys` 枚举路径统一改双区编址 helper；AOT 侧固定偏移读取随 `.an/.ai` 版本同步重生成。

### 4.4 与 AuxData Sidecar 同批实施

两项都触碰 hclass 内部契约：合并 bump 一次版本、一次 clean rebuild、一套新旧产物拒绝测试；实现顺序无依赖（不同数组），建议同一 AR 序列分两个 PR 上库，工具链改动共享。

### 4.5 方案利弊

| 方案 | 优点 | 代价 |
|---|---|---|
| **A 档：双区 6 B raw（无损退路）** | 全 41 bit 原样保留，写入者零语义变化 | 精算仅 10.42 MiB（对齐损耗大） |
| **B 档：双区 4 B raw + 迁移 13 运行时位（目标形态）** | 精算 23.17 MiB；追平 V8 压缩后条目宽度 | SortedIndex 迁移（推荐 Key 区 hash 有序化）牵动查找/枚举双链；标志位安置 |
| 交织编址 | 同收益 | 地址交错，编译侧改造面更大 |
| 跨 hclass Layout 共享（V8 家族式共享） | 基数级下降（0.9:1 → 分支点级） | transition 语义/AOT 布局依赖重构，二期评估 |

## 5、DFX 分析

- 可诊断性：dump/快照按 Key+Attr 逻辑视图输出属性表；rawheap metadata 同步新偏移；
- 可运维性：版本不匹配拒绝加载（沿用 `.an/.ai` strict match）；
- 可测试性：见第 7 节与需求 §5。

## 6、可信分析

- **可靠性**：GC 扫描区间收窄经 heap verification 与哨兵用例验证；两区长度一致性由单一来源 + 断言保证；
- **安全性**：不涉及输入解析/权限；**隐私/无害**：不涉及（内部布局改造）。

## 7、关键 DT 用例简述

| 测试用例名称 | 预置条件 | 用例关键步骤 | 预期结果 |
|--------------|----------|--------------|----------|
| 尺寸公式 | 双区布局构建 | 构造 N=1..33 的 Layout | `size == align8(16+12N)` |
| 属性查找全路径 | fast/dict/原型/AOT/PGO | 增删改查 + 枚举顺序 | 与现状逐字节一致 |
| Attr 区哨兵 | Layout 后放哨兵对象 | 压力 GC | 哨兵不变、无越界写 |
| 新旧产物互拒 | 旧 AOT + 新 runtime | 加载 | 稳定拒绝 |

| Top13 A/B | 双版本快照 | 逐数组 self_size | 降幅 ≥20 MiB 且符合公式 |

## 8、结论

方案设计完成，按「A 档 6 B 无损可先行 / B 档 4 B 为目标形态（依赖 SortedIndex hash 有序化迁移设计冻结）」实施；与 AuxData Sidecar 同批版本 bump。遗留问题见 `04-review-log.md`。
