# ConstantPool 跨 VM 共享与字面量优化 —— 背景

本文件存放理解本方案所需的背景知识与现有实现介绍。

## 1. ConstantPool 的共享边界（现状）

| 内容 | 当前归属 | 源码位置 |
|---|---|---|
| `JSPandaFile`（abc 元数据/字节码/字面量数据） | **跨 VM 共享**（shared_ptr） | `js_pandafile_manager.h:147` |
| **unshared ConstantPool** | **每 VM 一份**（`unsharedConstpools_` 数组，GC 每 VM 遍历） | `ecma_vm.cpp:505-512,1118-1120` |
| shared ConstantPool | 跨 VM 共享（sendable） | `Runtime::globalSharedConstpools_` |
| **字符串表（EcmaStringTable）** | **每 VM 一份** | `ecma_vm.h:1776` |

即：**abc 元数据已跨 VM 共享（JSPandaFile），但 unshared 池 resolve 出的对象（字符串、Method、ClassLiteral）每 VM 各一份**。

## 2. 多 Heap（多 VM）场景

ArkVM 一个进程可创建多个 `EcmaVM`（主 VM + worker VM）。每个 VM 加载同一 HAP 的 abc 时，各自创建自己的 unshared ConstantPool：

- 字符串常量（ConstantPool 条目 ~17.1%：模块路径、属性名、字符串字面量）在**每 VM 的字符串表各 intern 一份**，随 VM 数线性重复；
- Method / ClassLiteral 指向 VM 私有堆，不能直接跨 VM 共享；
- 但 ClassLiteral 已有 shared 版本（`NewSClassLiteral`，`program_object.cpp:47`），sendable class 的字面量已走 shared 路径。

## 3. 字面量机制（Array/Object 字面量）

- 字面量数据从 abc 提取（`LiteralDataExtractor`），`JSPandaFile` 跨 VM 共享；
- **对象字面量**：`GetObjectLiteralRootHClass`（HClass 按属性数缓存，**每 VM GlobalEnv**，`object_factory.cpp:4415-4436`）+ `CloneObjectLiteral`（深克隆 elements/properties/inline props，`object_factory.cpp:517-537`）；
- **数组字面量**：`CloneArrayLiteral`（`object_factory.cpp:539-560`）——**已有 COW 共享**：≤10 元素放 NON_MOVABLE，`ENABLE_COW_ARRAY` 时共享 elements 数组；
- 类字面量：`GetClassLiteralFromCache` 惰性 resolve（首次访问创建），有 local/shared 两版本。

## 4. 优化空间的两个子方向

- **子方向 A：Unshared ConstantPool 字符串常量跨 VM 共享**——多 VM 加载同一 abc 时，字符串条目在每 VM 重复 intern；
- **子方向 B：Array/Object 字面量优化**——对象字面量 HClass 缓存跨 VM、Properties/Elements COW 化、模板对象克隆（数组已部分 COW）。

## 5. 数据现状

- ConstantPool 总量 306.30 MiB（4,049 池，13 应用单 VM 快照，`evidence/top13-constantpool-snapshot-census.json`）；已 resolve 条目构成：method 54.2%、class_literal 17.4%、**字符串 17.1%**、js_object 6.4%、js_array 3.4%、tagged_array 1.3%；
- **ConstantPool 持有的字符串对象（去重后）**：685,129 个 / 15.38 MiB（13 应用合计，`evidence/top13-layout-dedup-census.json`）——这是每多一个加载同 abc 的 VM 的字符串重复**上界**（实际按 worker 加载的 abc 子集折减）；
- Method / ClassLiteral 指向 VM 私有堆不可跨 VM 共享（ClassLiteral 已有 sendable 版本），跨 VM 可共享的主体就是这 ~15.4 MiB 的字符串；
- `js_object` 83.69 MiB 中字面量对象占比未单独归因（快照无字面量标记），需专项统计；
- 多 VM（主 + worker）场景的 VM 数与每 VM 加载 abc 集未插桩统计。
