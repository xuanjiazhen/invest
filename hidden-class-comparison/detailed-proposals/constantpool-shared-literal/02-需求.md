# ConstantPool 跨 VM 共享与字面量优化 —— 需求

本文件描述方案收益、工作量与风险。

## 1. 方案目标

两个子方向（可拆为独立 AR）：

- **子方向 A（跨 VM 字符串共享）**：多 VM 加载同一 abc 时，ConstantPool 字符串条目跨 VM 复用（shared heap 字符串），消除每 VM 重复 intern。**量级已测定：单 VM 全量 15.38 MiB 去重字符串为主体**，绝对收益 = 15.38 MiB × (平均并发 VM 数 − 1) × worker 实际加载 abc 子集占比；
- **子方向 B（字面量优化）**：对象字面量 Properties/Elements COW 化、模板克隆降低创建成本（时间收益为主）。对象字面量 HClass 缓存经核算每 VM 上限为 `MAX_LITERAL_HCLASS_CACHE_SIZE+1` 个 root HClass（几十个 × 88 B ≈ 数 KB），收益可忽略，不纳入本方案。

## 2. 收益

| 子方向 | 收益口径 | 状态 |
|---|---|---|
| A 字符串跨 VM 共享 | 上界 15.38 MiB × (VM 数 − 1)，按 worker 加载子集折减；无 worker 的应用收益为 0 | 上界已量化，期望值待 worker 场景调研 |
| B 对象字面量 COW | 减少每次字面量创建的 elements/properties 克隆成本（时间）；空间取决于字面量对象规模 | 未量化（js_object 中字面量占比未归因） |

**前置量化**（B 及 A 的期望值，需先补）：
1. worker 使用率与每 worker 加载 abc 数（决定 A 的乘数；A 无 worker 场景则整体不立项）；
2. 从快照归因字面量对象规模（js_object 83.69 MiB 中字面量占比）。

## 3. 工作量与排期（估计，前置量化后细化）

| 任务 | 说明 | 人日 |
|---|---|---|
| 前置插桩统计 | worker 使用率与加载 abc 集、字面量对象规模 | 5–8 |
| A：字符串 shared-heap 化 | 字符串表共享/并发 intern + hash 并发安全 + shared heap 分配 | 15–25 |
| B：对象字面量 COW/模板克隆 | backing COW、写时复制、模板克隆 | 10–20 |
| 验证与回归 | shared GC、并发、worker、COW 写时复制 | 10–15 |

总量级：A 约 4–6 人周，B 约 3–5 人周（**需前置量化后细化**）。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| worker 场景不存在或 worker 不加载业务 abc（A 收益为 0） | 高 | worker 使用率调研为一票否决项；乘数为 0 则 A 撤项 |
| 字符串表跨 VM 共享与 GC 生命周期 | 高 | 复用 shared heap + EcmaStringTableMutex；worker teardown 清理表项不释放对象 |
| shared 字符串惰性 hash 回写数据竞争 | 高 | CAS/构建期预计算 + TSAN 用例 |
| COW 数组写时复制正确性 | 中 | 写屏障/读屏障覆盖；并发首次写入 |
| 与既有方案的收益重叠 | 中 | 字符串共享与方案 04（字符串优化）不重叠（一个是跨 VM 去重，一个是单 VM 内 intern 策略） |

## 5. 验收门槛（摘要）

1. 前置插桩数据明确：多 VM 字符串重复量、字面量对象规模；
2. 多 VM 场景字符串对象数随 VM 数不再线性增长（或下降符合模型）；
3. 对象字面量创建路径 COW 化后功能/性能回归通过；
4. shared GC / worker teardown / 并发 intern 无泄漏；
5. 快照对比确认收益。

## 6. 依赖

- 子方向 A 依赖 shared heap 字符串支持（sendable 字符串已有基础）；
- 子方向 B 依赖 read-only HClass 机制与 COW 数组（已有 ENABLE_COW_ARRAY 基础）。
