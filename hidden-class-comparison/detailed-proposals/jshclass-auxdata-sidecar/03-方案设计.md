# JSHClass AuxData Sidecar —— 方案设计（按架构特性设计模板）

## 1、特性需求/问题/动机的来源与价值

**问题来源**：Top13 快照观测 819,497 个 `JSHClass`（浅层堆 68.775 MiB）。其中 `ProtoChangeMarker`、`ProtoChangeDetails`、`EnumCache`、`DependentInfos` 四个 tagged 槽合计占每对象 32 B，但四字段非默认的并集仅 22,569 个（2.754%），97.2% 的 HClass 四字段全为默认值——固定内联造成确定性浪费。

**价值**：主对象 88 B → 64 B（-24 B/实例），稳态净收益模型 17.724 MiB，同时减少 GC body 扫描槽 36.1%（静态模型）。对低内存设备是确定性的浅层堆下降。

**实现前 vs 实现后（用户视角）**：实现前每个 shape 描述符固定 88 B；实现后为 64 B + 按需 sidecar，HClass 稀疏字段只在首次写入非默认值时分配，功能与可观测行为不变。

## 2、特性影响分析

### 2.1 系统位置

JSHClass 是对象模型核心，影响对象创建、属性访问、枚举、原型链、IC、GC、序列化、AOT/JIT 全链路。

### 2.2 环境依赖

- 单一布局：local / shared / read-only / AOT HClass 统一 64 B，不允许同一 `JSType::HCLASS` 混用 64/88 B 或按运行状态切换；
- 多 target/多 OS：与架构无关（64 位布局），无多后端差异。

### 2.3 涉及模块

runtime（`js_hclass.h/inl/cpp`、`object_factory`）、compiler（`CircuitBuilder`/`StubBuilder`/HCR/MCR/builtins stub）、GC（visitor/heap verification）、serializer/snapshot、AOT、hprof/rawheap、debugger/profiler、AppSpawn。

### 2.4 前后版本兼容性

- **不改变公开 API、字节码格式、JSFunction 对象布局**；JSHClass 无用户侧指针复制兼容约束，不是公开 ABI 阻塞项；
- JSHClass offset 是 **ArkVM 内部编译契约**：bump `.an/.ai` 版本 + strict match 拒绝旧产物；clean rebuild snapshot/AOT/stub；新旧版本混用必须稳定拒绝；rawheap metadata 更新为 64 B 布局，旧 translator 对新 rawheap 因版本不匹配失败。

### 2.5 外部用户感知

无（外部语义不变：枚举顺序、JSON.stringify、原型修改行为）。

### 2.6 性能影响

- 时间：首次 sidecar 分配进入 runtime slow path（mutex 二次检查）；已存在 sidecar 的 getter/setter 多一次间接访问；GC 扫描槽减少 36.1%（静态模型，须实测抵消）；
- 空间：主对象 -24 B/实例，sidecar +48 B×22,569 = 1.033 MiB，净 +17.724 MiB（浅层模型）。

## 3、业界竞品分析

| 引擎 | 对应结构 | 做法 |
|---|---|---|
| V8 | `Map`（~42 B） | 依赖 `DescriptorArray` 共享 + 迁移；`dependent_code` 用 `WeakArrayList`；无独立稀疏外提 |
| JSC | `Structure` | 单指针 transition + 属性表共享 |
| Hermes | `HiddenClass` | Transition 信息在 Property Map 中 |
| ArkVM（本方案） | `JSHClass` | 统一 64 B 主对象 + 4 槽 `TaggedArray` 强 sidecar |

ArkVM 当前 88 B 主对象大于 V8 Map（~42 B），稀疏字段外提是向紧凑元数据靠拢；与竞品不同，本方案用强引用 sidecar 而非弱表，避免 ephemeron/死键清理复杂度。弱表路线的完整评估见 §4.9。

## 4、本特性的设计/实现方案

### 4.1 目标布局（单一 64 B）

修改前后完整布局对比（偏移单位 B；「→ AuxData[n]」表示迁入 sidecar 对应槽）：

| 偏移 | 当前（88 B） | 目标（64 B） | 变化 |
|---:|---|---|---|
| 0 | TaggedObject header (8) | TaggedObject header (8) | 不变 |
| 8 | BitField (4) | BitField (4) | 不变 |
| 12 | BitField1 (4) | BitField1 (4) | 不变 |
| 16 | Proto (8) | Proto (8) | 不变 |
| 24 | Layout (8) | Layout (8) | 不变 |
| 32 | Transitions (8) | Transitions (8) | 不变 |
| 40 | Parent (8) | Parent (8) | 不变 |
| 48 | ProtoChangeMarker (8) | **AuxData (8)** | → AuxData[0] |
| 56 | ProtoChangeDetails (8) | **BitField2 (8)** | → AuxData[1]；BitField2 前移 24 B |
| 64 | EnumCache (8) | *（对象结束）* | → AuxData[2] |
| 72 | DependentInfos (8) | | → AuxData[3] |
| 80 | BitField2 (8) | | 前移至 56 |
| 88 | *（对象结束）* | | −24 B |

约束：`AUX_DATA_OFFSET=48`、`BIT_FIELD2_OFFSET=56`、`SIZE=64`。`DECL_VISIT_OBJECT` 扫描槽由 8 个（Proto/Layout/Transitions/Parent/四稀疏槽）降为 5 个（Proto/Layout/Transitions/Parent/AuxData）。

### 4.2 AuxData 编码

`AuxData` 只能是 `Null` 或长度为 4 的 `TaggedArray`（48 B）：

| 索引 | 载荷 | 初始化 |
|---:|---|---|
| 0 | `ProtoChangeMarker` | `Null` |
| 1 | `ProtoChangeDetails` | `Null` |
| 2 | `EnumCache` | `Null` |
| 3 | `DependentInfos` | `Undefined` |

不采用「单值直接编码、多值 sidecar」——`DependentInfos` 继承 `WeakVector` 无独立 `JSType`，运行时类型无法无歧义区分四种载荷。使用现有 `TaggedArray` 而非新增 `JSType`：现有 visitor/GC/write barrier/rawheap 已覆盖，不新增 meta-HClass 或全局容器。

### 4.3 Getter/Setter（统一 helper）

```text
GetAuxField(hclass, index, default):
    aux = acquire-load hclass.AuxData
    if aux is Null: return default
    return aux[index]

SetAuxField(hclass, index, value, default):
    aux = acquire-load hclass.AuxData
    if aux is Null and value == default: return
    if aux is Null: EnsureAuxDataAndSet(hclass, index, value); return
    aux[index] = value with write barrier
```

`EnsureAuxDataAndSet`：local 用 `NewOldSpaceTaggedArray(4)`；VM mutex 下二次检查（防止并发首次发布半初始化数组），release-publish；已有 sidecar 的普通 getter/setter 不加锁；不允许在 `DISALLOW_GARBAGE_COLLECTION` 区间首次分配。

### 4.4 Clone / transition / 状态迁移

不得整体共享 sidecar（EnumCache/marker/details/dependency 复制规则不同）。`Clone`/`CloneWithNewSizeAndType` 默认 `AuxData=Null`；`RefreshUsers` 只把 `ProtoChangeDetails` 从 old 移到 new 并清空 old；lazy-deopt 安装在当前 HClass 的 slot 3；迁移后断言 old/new sidecar 不是同一数组。

### 4.5 Compiled 路径

- getter 统一生成：`aux=Load(hclass+AUX_DATA_OFFSET)`；`aux==Null` 返回默认；否则 `Load(aux+DATA_OFFSET+index*8)`；
- setter：`aux!=Null` 用 `SetValueToTaggedArray`；`aux==Null && value==default` 直接返回；`aux==Null && value!=default` 调 runtime `EnsureHClassAuxDataAndSet`，不在机器码手写分配发布；
- 硬门槛：`JSHClass::PROTO_CHANGE_MARKER_OFFSET`/`JSHClass::PROTO_CHANGE_DETAILS_OFFSET`/`JSHClass::ENUM_CACHE_OFFSET`/`JSHClass::DEPENDENT_INFOS_OFFSET` 实现后仓库级引用数为 0。注意静态扫描必须按 `JSHClass::` 限定名匹配：`ENUM_CACHE_OFFSET` 存在同名的 `EnumCache` 自身字段偏移（`enum_cache.h:97-100`），非限定匹配会误报。

仓库级直接 offset 消费者冻结清单（源码核验，含测试共 7 个文件）：`compiler/circuit_builder.cpp`（EnumCache/Marker 读）、`compiler/stub_builder-inl.h`（Details/Enum/Dependent 写）、`compiler/hcr_circuit_builder.h:220`（Marker 读）、`compiler/new_object_stub_builder.cpp`（EnumCache 对象自身字段初始化，非 JSHClass 槽，改造时核对）、`serializer/base_serializer.cpp:180-188`（四字段重置）、`dfx/hprof/tests/js_metadata_test.cpp`（断言，随布局更新）。

### 4.6 「创建即分配」入口与 no-GC 审计

四个载荷的首次创建入口（sidecar 首次分配的触发点）冻结如下，实现时逐一审计其调用链是否存在 `DISALLOW_GARBAGE_COLLECTION` 区间：

| 载荷 | 创建入口 | 现状 |
|---|---|---|
| EnumCache | `JSObject::GetOrCreateEnumCache`（`js_object.cpp:742-750`） | 分配在句柄作用域内，无 no-GC 约束 |
| ProtoChangeDetails | `JSHClass::GetProtoChangeDetails`（`js_hclass.cpp:1288-1296`） | `NewProtoChangeDetails` 分配，调用链需逐点审计 |
| ProtoChangeMarker | 原型注册路径（`js_hclass.cpp:1080-1123` 一带） | 与 Details 成对，同链审计 |
| DependentInfos | `JSObject::GetOrCreateDependentInfos`（`js_object.cpp:753-763`）、lazy-deopt 安装 | lazy-deopt 安装在 compiler 线程，需确认锁与 no-GC 边界 |

`MarkProtoChanged`（`js_hclass-inl.h:379-399`）整体处于 `DISALLOW_GARBAGE_COLLECTION`，但只读两个槽、只写已存在载荷——sidecar getter 无分配，语义安全；若后续在 no-GC 区间新增写入，必须转 runtime slow path。

### 4.7 分阶段上库策略

直接切换 64 B 要求全量 clean rebuild（compiled offset、snapshot、AOT、stub 同时换版），无法渐进验证。建议拆三阶段，每阶段独立可回退：

| 阶段 | 布局 | 内容 | 内存 |
|---|---|---|---|
| S1 加槽 | 88 B → 96 B（新增 AuxData，四槽暂留） | helper + 四逻辑字段改为「写旧槽同时写 sidecar、读优先 sidecar」双路径；语义与 GC 验证 | -8 B（临时多一个槽，**内存回退**） |
| S2 删槽 | 96 B → 64 B | 全部消费者（compiled/serializer/工具）切到 AuxData，删除四槽，bump 版本 + clean rebuild | -32 B，到位 |
| S3 收尾 | 64 B | rawheap metadata、dump 逻辑字段名、旧 offset 引用归零进 CI | — |

S1 的 -8 B 临时回退只存在于过渡版本，不合入产品；S1/S2 之间可插入完整 correctness/GC 矩阵，把「compiled 全路径改造」（工作量表中 20 人日的关键路径）的风险前置拆解。

### 4.8 方案利弊

| 方案 | 优点 | 代价 |
|---|---|---|
| **统一 64 B + 强 sidecar（选）** | 单布局无双尺寸；无 ephemeron/弱表复杂度；生命周期由 GC 闭包 | 首次写入 slow path；compiled 全路径改造 |
| VM 级弱表（否决，评估见 §4.9） | 主对象可再省 8 B | 表本体 ~2.6–2.7 MiB + ephemeron fixpoint/死键清理/并发锁，净增益收窄至 ~4.6 MiB 且引入 GC 语义风险 |

### 4.9 弱表路线评估（可复用实现 / 增量工作量 / 影响模块）

**问题定义**：删除主对象 `AuxData` 槽（64 B → 56 B），四逻辑字段改存 VM 级弱表（key=HClass，value=载荷），HClass 死后表项可回收。

**① 可复用的既有弱结构（源码核验）**：

| 结构 | 位置 | 语义 | 直接复用性 |
|---|---|---|---|
| `JSWeakMap`/`EphemeronHashTable` | `js_weak_container.h:22`、`tagged_dictionary.h` | JS 层弱键哈希表，ephemeron 语义 | **最接近的可复用底座**：key 弱引用、value 强引用、死键清除均已有 GC 支持；但它是 JS 对象（有 meta-HClass、挂在 JS 堆上），VM 内部使用需去掉 JSObject 包装 |
| `WeakVector` | `weak_vector.h:24` | 弱引用数组（线性，无键查找） | 不适用——无法按 HClass 键寻址 |
| `TransitionsDictionary` | `transitions_dictionary.h:25` | 数值键哈希表，value/metaData 弱 | 部分复用——弱 value 处理先例；但键是 Number 不是对象指针 |

结论：没有「对象键 → 强 value」的现成 VM 内部弱表；最短路径是以 `EphemeronHashTable` 为底座去掉 JSObject 层，或新增一个走既有弱处理器的专用 `HClassAuxDataTable`（结构可照抄 `TransitionsDictionary` 的弱值模式反向）。

**② 增量工作量（相对强 sidecar 方案的 80 人日）**：

| 任务 | 人日 |
|---|---:|
| 表结构与 GC 集成（ephemeron 标记、死键清除、不动点迭代路径接入） | 8–10 |
| VM 根注册与跨线程（compiler 线程写 DependentInfos 需表级锁或分段锁） | 4–6 |
| 访问路径改哈希查找（C++ helper + compiled 路径需 runtime call，无法生成内联 fast path） | 5–7 |
| TSAN/并发/弱语义专项测试（HClass 死亡瞬间的读写竞态） | 5–7 |
| **合计增量** | **22–30 人日** |

**③ 影响模块**：GC（ephemeron fixpoint、死键清除、shared GC 排除）、runtime（VM 根、表锁）、compiler（弱表读写不能内联到机器码，只能走 runtime call——**compiled fast path 消失**，for-in/原型检查热路径每次多一次调用）、DFX（dump/快照需遍历表回填逻辑字段）。

**④ 内存账（Top13 口径）**：22,569 项、`ComputeCapacity` 需 65,536 桶 → 数组本体 2.000 MiB + 每项 entry（hash+key+value ≈ 24 B）×22,569 ≈ 0.52 MiB + 根/锁常量 ≈ **稳态 ~2.6 MiB**（另有 rehash 双倍瞬时峰值）。相对强 sidecar（1.033 MiB）多花 ~1.6 MiB，换取主对象再省 8 B×819,497 = 6.25 MiB，**净增益上限 ≈ +4.6 MiB**。

**⑤ 结论**：弱表路线技术上可行（有 EphemeronHashTable 底座），但需 +22–30 人日、compiled fast path 退化为 runtime call（与 §9.4 性能门槛冲突风险高）、GC 语义风险等级升高，换取的确定性净增益仅 ~4.6 MiB。维持 §4.8 决策：**首选强 sidecar；弱表作为二期探索项，仅当 PSS 实测显示 64 B 仍不达标且 4.6 MiB 成为关键缺口时再立项**。

## 5、DFX 分析

- 可诊断性：`dumpHClass` 通过逻辑 getter 输出原字段名；heap snapshot/rawheap 保留 `AuxData` 边并映射回四逻辑字段；
- 可运维性：布局版本纳入 `.an/.ai`/rawheap metadata，版本不匹配拒绝加载；
- 可测试性：见第 7 节 DT 用例与附录。

## 6、可信分析

- **可靠性**：弱引用处理器/GC visitor 覆盖 sidecar；并发首次写入有 mutex 防护；不引入 ephemeron 不动点迭代（规避弱表正确性风险）；
- **安全性**：不涉及输入解析/权限；
- **韧性/可用性/隐私/无害**：不涉及（内部内存布局改造，外部行为不变）。

## 7、关键 DT 用例简述

| 测试用例名称 | 预置条件 | 用例关键步骤 | 预期结果 |
|--------------|----------|--------------|----------|
| 并发首次写不同槽 | 两线程、同一 HClass | 同时 SetAuxField 不同 index | 两个值最终都存在，无半初始化数组 |
| 首写前后 GC | young/full GC 触发 | 首次写入前/后强制 GC | sidecar 与载荷可回收/存活正确 |
| Clone 不共享 sidecar | 有 sidecar 的 HClass | Clone 后校验 old/new | old/new AuxData 非同一数组 |
| 枚举失效 | 创建 EnumCache 后改原型 | for-in 触发失效 | 枚举缓存正确失效 |
| shared 非法写入 | shared HClass | debug 构建 SetAuxField | 触发断言 |
| 版本拒绝 | 旧 AOT/rawheap | 新 runtime 加载 | 稳定拒绝 |
