# JSHClass AuxData Sidecar —— 需求

本文件描述方案收益、工作量与风险，供项目管理者与评审决策。

## 1. 方案目标

将 `JSHClass` 从 88 B 缩减到 64 B：删除 `ProtoChangeMarker`、`ProtoChangeDetails`、`EnumCache`、`DependentInfos` 四个稀疏槽，增加一个 8 B `AuxData` 强引用槽（指向长度 4 的 `TaggedArray` sidecar），单实例净缩减 24 B。

## 2. 收益

| 指标 | 值 |
|---|---|
| 主对象毛收益 | 819,497 × 24 B = 18.757 MiB |
| sidecar 成本 | 22,569 × 48 B = 1.033 MiB |
| **稳态净收益模型** | **17.724 MiB**（相对当前浅层堆降幅 25.771%） |
| GC body 扫描槽 | 6,555,976 → 4,187,761（-36.123% 静态模型） |

最终放行以实现后的 clean A/B（PSS + 浅层堆）为准，模型不替代实测。

## 4. 风险

| 风险 | 等级 | 控制条件 |
|---|---|---|
| compiled builder 直接读写四个旧 offset（`circuit_builder.cpp:763-774`、`stub_builder-inl.h:2459-2493`、`hcr_circuit_builder.h:220`） | 高 | 统一 AuxData fast path；旧 offset 仓库级引用数归零为硬门槛 |
| 首次 sidecar 分配的并发发布 | 中 | VM mutex 二次检查 + release-publish，禁止发布半初始化数组 |
| 「创建即分配」入口落在 no-GC 区间 | 中 | 冻结四个创建入口清单（方案设计 §4.6），逐调用链审计；lazy-deopt 安装在 compiler 线程需单独确认 |
| JSHClass offset 是 ArkVM 内部编译契约 | 中 | bump `.an/.ai` 版本、clean rebuild、新旧产物稳定拒绝；按 §4.7 三阶段上库拆解风险 |
| shared/read-only HClass 边界 | 中 | 当前四字段保持默认；shared setter 保留 ShareToLocal 禁止语义 |
| GC 性能回退（对象头增加、分散访问） | 中 | 静态扫描模型只是参考，须实测 young/full/shared GC 扫描字节/暂停/CPU |
| JIT-enabled 场景 sidecar 覆盖率未实测 | 中 | Top13 基线为 JIT-off 快照；JIT/AOT 开启构建上需复测四字段联合分布（lazy-deopt 安装会写 DependentInfos 槽），确认覆盖率与 break-even 余量 |

## 5. 验收门槛（摘要）

- **正确性**：interpreter/IC/PGO/AOT/baseline JIT/fast JIT、lazy-deopt、for-in/JSON 枚举、Clone/transition、shared/read-only、GC 矩阵 100% 通过；
- **内存**：Top13 新快照 `JSHClass.self_size=64`，主对象+sidecar 浅层堆净降 ≥17.0 MiB，PSS 中位数不得回退、13 应用中位数下降之和 ≥10 MiB；在 JIT/AOT-enabled 构建上另采一份四字段联合分布快照，sidecar 覆盖率不得突破 break-even（50%）；
- **性能**：for-in/原型修改中位数回退 ≤3%（任一 workload ≤5%）、AOT/JIT 几何平均 ≤1%、冷启动 P50 ≤1%、GC pause ≤2-5%；
- **静态**：`JSHClass::SIZE==64`、`TaggedArray::ComputeSize(8,4)==48`、旧四 offset（`JSHClass::` 限定）引用数 0。

## 6. 依赖

- 无新编译宏/新能力依赖；与「编译宏 VM 分档（JIT-off）」正交（本方案不删任何 JIT 专用字段，完整保留 lazy-deopt/IC/AOT 语义）。
