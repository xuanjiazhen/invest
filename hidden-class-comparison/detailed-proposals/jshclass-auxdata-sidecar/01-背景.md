# JSHClass AuxData Sidecar —— 背景

本文件存放理解本方案所需的背景知识与现有实现介绍，供不具备上下文的新成员快速对齐。

## 1. JSHClass 是什么

`JSHClass` 是 ArkVM 的对象形状（shape）描述符，等价于 V8 的 `Map`、JSC 的 `Structure`。每个 JS 对象的对象头都持有指向其 `JSHClass` 的指针，属性访问、对象创建、枚举、原型链操作都依赖它。

## 3. 四个稀疏字段的语义（本方案的目标）

| 字段 | 所有权与生命周期 | 主要路径 | 默认值 |
|---|---|---|---|
| `ProtoChangeMarker` | HClass 持有，记录原型链变化状态 | 原型注册、IC/AOT 失效通知 | `Null` |
| `ProtoChangeDetails` | HClass 持有，包含 listener 与注册索引 | 原型链注册、迁移、刷新用户 | `Null` |
| `EnumCache` | HClass 持有，按枚举路径创建并失效 | `for...in`、对象键枚举、原型变化 | `Null` |
| `DependentInfos` | HClass 持有，保存函数与依赖集合 | JIT lazy-deopt 依赖安装和触发 | `Undefined` |

四个字段用示例代码展开（每条给出：触发代码 → VM 内部动作 → 用户可感知效果）：

### 3.1 EnumCache —— for-in 枚举缓存

```js
const obj = { a: 1, b: 2 };
obj.__proto__ = { c: 3 };
for (const k in obj) { print(k); }   // 第一次：沿原型链逐层收集 key → 写入 obj 的 HClass.EnumCache
for (const k in obj) { print(k); }   // 再次：直接复用 EnumCache，跳过逐层收集
```

- VM 动作：首次 for-in 时 `JSObject::GetOrCreateEnumCache`（`js_object.cpp:742-750`）创建并挂到 HClass；
- 可感知效果：重复枚举同一 shape 的对象更快；原型链被修改时 `MarkProtoChanged` 将缓存置失效（`js_hclass-inl.h:379-399`），下次枚举重新收集且顺序语义不变。

### 3.2 ProtoChangeMarker —— 原型链变化的版本标记

```js
function Foo() {}
const f = new Foo();
f.x;                                  // IC 建立快速访问路径（记录当时原型链状态）
Foo.prototype.x = 42;                 // 原型被修改 → Foo.prototype 的 HClass 写 ProtoChangeMarker
f.x;                                  // IC 检查 marker 发现版本变化 → 丢弃旧路径重新查找
```

- VM 动作：原型对象被修改/注册为原型时创建 marker 并在其后置「已变化」；
- 可感知效果：保证 `f.x` 在原型修改后立刻看到新值（正确性字段，非纯优化——关闭 JIT 仍需要）。

### 3.3 ProtoChangeDetails —— 原型变更的监听者登记

```js
const proto = { greet() { return 'hi'; } };
const o1 = Object.create(proto), o2 = Object.create(proto);
o1.greet(); o2.greet();               // 使用 proto 的对象可被登记到 proto 的 HClass 监听列表
Object.setPrototypeOf(o1, null);      // o1 的 HClass 换原型 → 通过 Details 迁移/注销登记
proto.greet = () => 'hello';          // 变更时按 Details 刷新（RefreshUsers）依赖旧 shape 的用户
```

- VM 动作：注册原型时 `GetProtoChangeDetails`（`js_hclass.cpp:1288-1296`）创建 listener 列表；`RefreshUsers`（`js_hclass.cpp:1309-1325`）在 HClass 迁移时把 Details 移交新 HClass；
- 可感知效果：原型替换/属性注入后，依赖方（含 AOT 场景）不读到过期 shape。

### 3.4 DependentInfos —— JIT lazy-deopt 依赖集合

```js
class Config { static readonly THEME = 'dark'; }
function render() { return Config.THEME; }   // JIT 优化时假设 THEME 恒为常量，把依赖登记到该 HClass
// ... render 被热点编译 ...
Config.THEME = 'light';                       // 修改常量字段 → 触发登记的依赖 → lazy-deopt 丢弃优化代码
```

- VM 动作：优化代码安装假设时经 `lazy_deopt_dependency.cpp:43-54` 把函数登记进 HClass 的 `DependentInfos`（弱引用载荷）；假设被打破时触发失效；
- 可感知效果：优化代码不会基于过期假设返回错误结果；Top13（JIT-off 采集）中仅 5 个非默认槽，JIT-enabled 场景该槽更活跃。

重要语义：`ProtoChangeMarker/Details` 与 `EnumCache` **不是 JIT 专用字段**——关闭 JIT 也不能删除这些语义（它们服务解释器下的枚举、原型变更与 IC 失效）。`DependentInfos` 明确服务 JIT lazy-deopt，但 Top13 实测仍有 5 个非默认槽，不能按「无 JIT」作为删除前提。

## 5. 现有机制要点（背景知识）

- **Transitions 已是弱引用**：单后继存 `weakChild`（`js_hclass-inl.h:39-40`），多后继 `TransitionsDictionary` 的 value/metaData 也是弱引用（`transitions_dictionary.h:113-120`）——transition 中间态早已可被 GC 回收，本方案与其正交；
- **Parent 是强引用**：`child->SetParent(parent)`（`js_hclass-inl.h:333`），子 HClass 强引用父 HClass；
- **Heap Snapshot self_size**：`hclass.self_size=88` 只表示 JSHClass 自身浅层大小，不含 Layout/Transitions/EnumCache 等指向的独立堆对象，也不含业务对象的 in-object 槽、Region committed/resident 或 PSS；
- **rawheap 边语义**：V2 转换器对 `ZERO_VALUE`/整数/double 返回空边（`rawheap_translate.cpp:1776-1797,1822-1844`），命名字段边仅在槽内是堆引用时生成——因此可以直接统计四字段的非默认占用。
