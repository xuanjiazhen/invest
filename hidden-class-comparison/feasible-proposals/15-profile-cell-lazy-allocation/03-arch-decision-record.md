# 架构决策记录（ADR）：ProfileTypeInfoCell 按需分配

## 状态

提议，等待定位表示 spike 和生命周期插桩。

## 背景

实际 cell 当前在函数定义阶段创建，但其共享身份由父 `ProfileTypeInfo[slotId]` 所有。将创建推迟到首次反馈可以降低冷函数驻留，却不能丢失这份父 slot 所有权。

## 决策

优先验证“首次反馈/PGO 触发时创建”，不引入执行次数阈值。候选实现必须在首次触发时恢复原父 `ProfileTypeInfo + slotId`，将 cell 写回父 slot，并让同一位置的闭包继续指向同一 cell。

在下列条件全部满足前保持现状：

1. 定位表示无歧义；
2. 同 slot 多闭包共享和 `CELL_0/1/N` 消费语义等价；
3. PGO `Handle` 采集完整；
4. 新增元数据纳入 GC/serializer/snapshot；
5. 扣除元数据后净收益为正。

## 权衡

| 方案 | 优点 | 代价/结论 |
|---|---|---|
| 首次反馈/PGO 触发（候选） | 冷函数无需实际 cell | 需要恢复父 slot，先做 spike |
| 执行次数阈值触发 | 可控制创建时机 | 新增计数，且仍不能解决父 slot 定位；否决 |
| 每个闭包首次反馈时建立私有 cell | 实现简单 | 破坏同 slot 共享；否决 |
| 保持即时分配 | 语义与性能稳定 | 保留 32 B/cell 驻留；作为门槛未通过时的默认方案 |

## 与裁槽方案关系

本候选只改变 cell 数量，不改变 cell 字段布局。`MachineCode`/`Handle` 的编译期裁槽独立设计、独立放行、独立核算，不以本 ADR 通过为前提。
