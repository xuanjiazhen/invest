# 架构决策记录（ADR）：LayoutInfo 共享

## 决策

以「**内容等价共享**」为主体（族内零拷贝继承 + 跨 context 内容寻址 intern），V8 式「前缀家族 slack 共享」降为可选跟进项；共享的前提是就地变更的写时复制/族内一致化框架。

## 理由

1. 数据：键序列等价去重贡献收益的 96%（54.00/56.35 MiB），前缀链共享仅 +2.35 MiB——把工程重心放在重复消除而非链共享；
2. 机制：ArkVM 已有 Clone 家族共享同一 Layout 数组的运行先例，族内共享（proto/extensible 零拷贝）是该先例的自然延伸；跨 context intern 则复用「interned 字符串表」的成熟模式；
3. 风险排序：两条路径都卡在同一前置（就地变更隔离），先做变更隔离框架，族内共享立刻可用，intern 表随后叠加。

## 备选与否决

| 方案 | 判定 |
|---|---|
| 前缀家族共享为主体（V8 原型直接迁移） | 收益增量小（2.35 MiB），却同样承担变更隔离成本——降级为 A 落地后的可选项 |
| 仅族内共享，不做跨 context intern | 漏掉收益主体（跨 context 重复）；且 intern 表与字符串表同构，增量成本可控 |
| hclass 级全 COW（每次变更拷贝整组，不改现状） | 即现状，54 MiB 浪费保留 |
| 引用计数所有权标记 | GC 堆对象不宜引入 refcount；用「独占者指针」（数组头尾保留 owner hclass 槽或 hclass 侧 owner 位）替代 |

## 变更隔离策略（待冻结的二选一）

1. **族内一致化**：TrackType 等演化对同 shape 家族单调收敛（V8 field-type generalization 同型）——零拷贝、零运行时开销，但需语义证明与去precated 路径审计；
2. **COW**：任何就地变更前检查独占所有权，非独占则拷贝——实现直接，代价是首次变更时恢复一次拷贝（重复度降低后可接受）。

倾向：TrackType 取一致化、attr 更新/标志位取 COW（或经 14-B 迁移后消失）——组合策略在实现阶段以语义审计结论定稿。

## 后果

- LayoutInfo 从「每 hclass 私有」变为「内容寻址的共享不可变值 + 受控变更」——接近字符串 intern 模型；
- 14（attr 压缩）的基数随共享落地缩水至 ~19 万数组，两项必须合并排期：**先 16 后 14**，14-B 档 23.17 MiB 预期按同比例缩至 ~6 MiB（届时以 14 的 A 档 6B 编码为收尾更划算）；
- serializer/rawheap/dump 需感知共享（多 hclass 指向同数组的边输出与归因）。
