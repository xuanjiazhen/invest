# 应用启动性能分析要点

按真实启动关键路径解释每段花了多久、慢在哪个组件、哪个动作值得优化、如何复测。用[案例报告](../report.spec.md)及其[切片索引](../startup-timelines/timeline-marks.csv)查看交付示例。需要从大型原始 trace 提取证据时，可参考仓库的 [HarmonyOS 启动 Trace 分析技能](../../.agents/skills/harmony-startup-trace-analysis/SKILL.md)。

## 确认测量口径

- 记录设备、系统与应用版本、启动入口、包模式、预加载和缓存策略、采集配置及有效样本规则。进程冷启动逐轮确认旧目标进程退出和新 PID；同时说明系统缓存状态。竞品对照保留硬件、系统、应用和采样条件差异。同机 A/B 尽量只改变待验证的优化。
- 用原始事件定义起止。区分主界面创建、App 首绘、系统启动上报、帧实际呈现和业务可交互。跨平台使用可比较的里程碑，说明各端标记的语义和剩余差异。硬件、系统和包同时变化时，端到端差值归于整套配置。归因到单一组件需要独立证据或控制变量实验。
- 记录试采、无效轮次及剔除理由。按有效样本报告轮数、均值和适用的离散指标。若端到端采样与带 trace 的分段采样来自不同批次，分开报告。时间轴采用可追溯的代表轮，注明样本 ID 和选择依据。逐轮取值后再汇总分段，保留单轮值和统计分母。确认未发生的事件可计零，采样缺失应单列。

## 对齐全程与子图

- 每轮以同一个启动事件为零点。按实际 trace 锚点建总图，可从系统启动请求、应用初始化、主界面至首绘、首绘至系统上报四段起步。每个子图使用父段的原始起止，在图顶用全程缩尺标出位置，横轴仍用距启动请求的时间。跨设备直接比较长短时共享刻度，各自放大时注明比例。
- 用原始整数时间戳核对。父段由首尾相接的互斥子区间完整覆盖，子段之和等于父段。保留切片间隙和未归因时间，按交界裁剪跨段切片。对交叠的同线程活动计算区间并集，必要时区分各类独占及重叠时间。先复算，再统一显示精度。
- 同一 TID 只占一条泳道，嵌套调用在该泳道加标记。另一 TID 才另起泳道。跨组件的墙钟主路径单独标明。主线程等 worker 的窗口与 worker 执行共用一次经过时间。用调度状态确认实际运行重叠，用唤醒、等待对象或 IPC 事务证据确认依赖。区分运行、就绪、睡眠和不可中断状态。仅凭睡眠或不可中断状态无法判定具体等待对象或磁盘 I/O。
- 图上保留层级编号、刻度和线程名，图下解释编号、组件、动作与耗时。父子图应可互相定位。按证据与影响选择展开粒度。约 10 ms 的短子段通常留在父图，案例把 10–12 ms 也按短段处理。短项的耗时照常计入，密集短项按类别汇总；只有能解释关键路径或累计影响时才继续放大。

## 给仓颉与原生库归因

- 从兼容桥开始加载追到业务 entry 包初始化结束，按实际切片区分兼容互操作 loader、系统互操作与原生 FFI、仓颉运行时及其原生支撑、TPC、标准库与扩展库、OHOS API、Kit API、兼容差分库、业务仓颉库和其他应用或系统库。单列穿插其间的 ArkTS 求值、NAPI 初始化与原生依赖。继续核对窗口与前台回调里是否有仓颉任务。
- 把 `.so` 查找、打开与映射、重定位与链接、ELF 构造器、仓颉运行时创建、包与类型注册、业务包初始化按实际边界计时。区分首次装载、复用已有映射、后续打开同名库和重新执行构造。用实际路径、加载器事件或相应时点的进程 maps 核对。单次 `dlopen` 或事后 maps 只说明其各自覆盖的观察结果。构造器切片数、去重库数和映射次数分别统计。
- `dlopen`、加载和重定位通常覆盖依赖闭包。只有具备逐库埋点的动作才能给出逐库实测耗时，例如带路径的构造器。闭包内的构造器和嵌套注册已含在外层时长中。若只有 ELF 文件大小、`DT_NEEDED`、重定位条目数、源码路径或模型分摊，注明对应证据类型。需要逐库解释时，补实际路径、namespace、复用状态、映射、重定位和构造埋点。
- 保留每条证据的样本、阶段编号、PID/TID、事件、请求名与实际路径、原始时间、裁剪后时间、trace 行号或 `slice.id`。有区间和标签即可回查的精简索引可随报告提供。检查解析器是否漏掉含空格的线程名、截断切片或异步事件。缺失埋点时说明当前可见范围和补采方式。

## 估算收益与验证

- 兼容包与系统库对照时，核对真机镜像的实际 SDK 库目录和依赖闭包，例如 `/system/lib64/platformsdk/` 及设备上的仓颉 SDK 子目录。以实测启动时所用路径为基线，逐库记录原路径、目标路径、迁移或移除状态和耗时口径。覆盖迁移到系统库的运行时、标准库、API 与原生支撑，以及移除的兼容 loader 和差分库。镜像同名库只证明有候选项，仍要验证 namespace 可达、ABI 与符号、实际加载来源及映射复用。切换路径后仍可能发生每进程初始化、重定位和包注册。
- 用两条对齐的时间轴呈现实测基线与优化后实测或预计。每个改动写明负责组件、受影响的阶段、具体库或调用、可节省的动作、仍会发生的动作、证据与验证指标。仅对可能推进启动终点且互不重复的区间计入预计收益。缺少同机 B 组时，只有证据足以建模才给估算值，并列明假设和验证方法。证据不足时标明收益待测及所需证据。
- 优先处理覆盖关键路径且可以核验的长段。验证时同时看目标切片、启动总指标和关键后续动作。需要延期加载时，一并检查首屏功能与延期功能的首次使用成本。

## 交付复核

- 核对总图、子图、表格及索引的编号、时间锚点、计量单位与来源。检查每张图能否独立定位回全程，统计表的总值能否从同一批样本复算。验算父子区间边界、同线程嵌套及跨线程重叠。
- 让无项目背景的开发者从总图开始阅读，独立指出慢段在全程哪里、属于哪个线程与组件、哪些结论已测、下一步该测什么。用反馈检查图表标记、术语和证据链接，修正后复核实际交付件。
