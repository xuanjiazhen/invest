# 业界中间表示（IR）调研计划

## 1. 调研目标

按类别整理业界公开 IR，查证每项 IR 的所属项目、抽象层级、表示结构、支持语言、公开用途和项目状态，重点记录具备多语言输入、共享运行时格式或多方言扩展能力的 IR。

## 2. 范围与边界

### 2.1 纳入范围

- 编译器由源码或上一级程序表示生成的高层、中层、低层 IR。
- 虚拟机、可移植字节码和 GPU/AI 等领域专用 IR。
- 面向静态分析、程序转换和形式化验证的 IR。
- 面向源码规范化、二进制提升、值流分析和验证条件生成的静态分析专用表示。
- 有公开规范或官方资料的历史项目。

### 2.2 区分处理

- AST/HIR、字节码、虚拟 ISA 与编译器 IR 均可纳入，但必须明确其边界和消费方。
- SSA、三地址码、Tree、DAG 属于结构或性质，不与具体项目 IR 并列统计。
- 已停止维护或被替代的 IR 标记为历史状态。
- 图式程序模型、验证中间语言和求解器输入与指令式 IR 分组记录，不混用名称。
- 无法由一手资料确认的名称或能力不进入报告。

## 3. 分析框架

每个代表性 IR 按以下维度记录：

| 维度 | 判定内容 |
|---|---|
| 生成位置 | 源码前端、语义分析后、中端、后端、运行时或领域编译器 |
| 抽象层级 | 高层、中层、低层、多层级 |
| 表示结构 | Tree、CFG、SSA、图、栈式、寄存器式、操作/区域等 |
| 语义保留 | 类型、对象模型、泛型、所有权、异常、控制流、内存模型 |
| 语言覆盖 | 单语言、多语言、领域输入、跨前后端复用方式 |
| 主要用途 | 优化、分析、转换、验证、解释/JIT、可移植分发、硬件映射 |
| 扩展机制 | 方言、Pass、插件、序列化格式、API 与工具链 |
| 项目状态 | 维护主体、代码托管、公开文档、发布或归档状态 |
| 学术记录 | 定义论文、DOI、DBLP/OpenAlex/Semantic Scholar 索引记录 |
| 专利记录 | 明确提及具体 IR 名称及分析用途的专利公开号、标题和检索链接 |

## 4. 资料收集方法

### 4.1 证据优先级

1. 标准规范、项目官方文档、语言参考和官方仓库源码。
2. 维护机构的设计文档、开发者文档、发布说明与论文。
3. 可信技术社区或维护者演讲，仅用于补充解释。
4. 聚合文章和搜索摘要仅用于发现线索，不直接支撑项目事实。

### 4.2 通用网页检索

- 使用项目名与 `IR design`、`intermediate representation`、`compiler pipeline`、`language support`、`SSA`、`bytecode` 等组合查询。
- 对项目名称、语言覆盖、表示结构、用途和状态回到官方规范或仓库核验。
- 记录访问日期；对项目状态标明截至 2026 年 7 月。

### 4.3 开源托管平台专项检索

| 平台 | 专项检索目标 | 重点检查项 |
|---|---|---|
| GitHub | LLVM/MLIR、Swift、Rust、Kotlin、Soot、WALA、Graal、TVM、OpenXLA、ELVM 等 | 官方归属、源码目录、README、提交与发布、扩展生态 |
| GitLab | 平台内 IR/MLIR/compiler 项目与官方镜像 | 独立实现、镜像关系、活跃度、许可证 |
| Gitee | 国内镜像与编译器/静态分析项目 | 是否为官方源、同步状态、文档完整度 |
| GitCode | OpenHarmony、方舟相关项目及国内开源实现 | 官方仓归属、IR/字节码实现位置、生态关联 |

平台检索结果区分“官方主仓”“官方镜像”“社区镜像”“衍生项目”，只记录可核验的仓库身份和公开状态。

### 4.4 论文与专利专项检索

- 论文检索使用 DBLP、OpenAlex、Semantic Scholar、DOI 页面和项目论文列表，记录定义论文及可核验的索引条目。
- 专利检索使用 Google Patents、WIPO Patentscope 等公开入口，以具体 IR 名称和 `static analysis`、`binary analysis`、`taint analysis`、`program verification` 组合查询。
- 专利只记录公开文本或检索摘要明确出现具体 IR 名称及用途的条目；未检索到不等同于不存在。
- 论文和专利用于补充表示来源与公开应用记录；项目结构、输入和当前状态仍回到官方规范、文档或仓库核验。

## 5. 报告结构

1. 调研范围与分类口径。
2. 多语言 IR：多前端共享 IR、多语言运行时格式、多方言基础设施。
3. 语言专属 IR。
4. 程序分析与代码转换 IR：源码规范化 IR、二进制提升 IR、图式程序表示、验证中间语言和程序模型。
5. 稳定字节码与虚拟指令格式。
6. AI、GPU 与异构计算 IR。
7. 历史和研究型 IR。
8. 开源托管平台中的仓库身份与公开状态。
9. 参考资料。

## 6. 交付件

- `ir/req.spec.md`：原始需求与初步清单。
- `ir/plan.spec.md`：调研范围、方法和交付标准。
- `ir/report.spec.md`：正式调研报告。
- `ir/industry-ir-research-slides.html`：交互式汇报幻灯片。
- `index.html`：新增且仅新增 slides 入口。

## 7. 质量与验收标准

- 每项 IR 的名称、定义、语言覆盖和用途至少由一项一手资料支持。
- 静态分析 IR 同时记录官方实现或规范、定义论文或学术索引；存在直接相关专利时记录公开号和检索链接。
- 报告中的项目链接可访问，托管平台项目身份已区分。
- 初步清单中的错误归类、过时项目和概念项不进入正式分类表。
- 报告与 slides 的分类、命名、语言覆盖和用途一致。
- 报告与 slides 不包含 AI 生成的总结、推断、优劣判断、选型建议、启示或行动建议。
- slides 支持键盘、按钮和触摸导航，适配桌面与移动视口，无内容溢出。
- `index.html` 仅链接 HTML slides，不出现 Markdown、Draw.io、SVG 或 PNG 入口。
- 最终产物不包含过程性叙述关键词或临时审查材料。
